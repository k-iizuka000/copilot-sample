# 詳細設計ワークフロー v3.1.0

Excel設計書を、出典付きのJSONに整理してから、責務ごとに分けた詳細設計Markdown（`spec/`）へ変換するGitHub Copilot用のパッケージです。
VS Code のチャット欄に決まった命令を打つだけで進みます（Windows・PowerShell のみで動作、Python 不要）。
コード実装・実装計画・テスト生成は対象外です（設計書の構造化だけを扱います）。

### 用語メモ（先に読んでおくと迷いません）

- **Copilot Chat**: VS Code の右側に出る、AI と会話する欄。ここに `/命令` を打って使います。
- **プロンプト（`/01-setup` など）**: あらかじめ用意した命令。チャット欄で `/` を打つと候補が出ます。
- **run-template**: 1つの機能を変換するための作業フォルダの雛形。コピーして使います。
- **JSON**: 設計書の中身を、機械が読める形に整理した中間データ。
- **`spec/`**: 変換結果（詳細設計Markdown）が入る、最終出力のフォルダ。
- **`runs/`**: 変換の作業途中ファイルが入るフォルダ。作業が終われば消してかまいません。
- **verify.ps1**: 出力が壊れていないかを自動でチェックする PowerShell スクリプト。
- **プロファイル**: 設計書の種類ごとの読み取り方の定義。役割が書かれていない設計書は、これで役割を推定します。

## 1. これは何か

Excel設計書 → 出典付きJSON → 詳細設計Markdown（`spec/`）へ、AI が半自動で変換します。
毎回同じ命令を繰り返し打つだけで進むので、「次は何をすればいいか」を人が考える必要はありません。

## 2. 導入手順（最初に1回だけ）

1. このパッケージの中の **`.github` フォルダ**・**`.vscode` フォルダ**・**`spec-format` フォルダ** の3つを、設計書を変換したいリポジトリの一番上（ルート）へコピーします（`spec-format` は出力形式の正本で、プロンプトが参照するため必須です。`docs` はコピー不要です）。
2. コピー先にすでに `.vscode/settings.json` がある場合は、**上書きしない**でください。
   このパッケージの `settings.json` にある `chat.promptFilesLocations` と `json.schemas` の2項目を、既存ファイルに継ぎ足してください（分からなければ担当者に相談を）。
3. VS Code を再読み込みします。コマンドパレット（`Ctrl` + `Shift` + `P`）を開き、`Reload Window` と入力して Enter。
4. 動作確認: Copilot Chat の入力欄で `/01-setup` と打ち、候補に `01-setup` が出れば準備完了です。

## 3. 1つの機能を変換する流れ

### 手順1: 作業フォルダを用意する

1. `/.github/skills/detail-design-workflow/run-template/FEATURE-ID/` フォルダをコピーします。
2. コピー先はリポジトリのルート直下の `runs/` の中。フォルダ名 `FEATURE-ID` を、変換する機能のID（例: `FUNC0123`）に変えます。
   → 例: `runs/FUNC0123/`
3. 変換したい設計書を CSV または TSV に書き出し、`runs/FUNC0123/00-input/` に置きます（Excel を Copilot が直接読めないときの前準備。人が行います）。
4. `runs/FUNC0123/run-request.json` をテキストエディタで開き、機能ID・機能名・ID種別・設計書ファイル名などを実際の値に書き換えます。

### 手順2: `/01-setup` で棚卸しする（1機能につき1回）

1. Copilot Chat を開き、モデルを **GPT-5.4** に切り替えます。
2. 入力欄に `/01-setup` と打って Enter。
3. 設計書のシートを分類した結果（J-01 という JSON）が `10-json/` に作られます。
   チャットの最後に「次は `/02-run` を実行」と案内が出れば成功です。

### 手順3: `/02-run` を繰り返す（案内が終わるまで）

1. Copilot Chat の入力欄に `/02-run` と打って Enter。1回につき1つの作業（抽出や1ファイル生成）だけ進みます。
2. 実行のたびに、冒頭で「今回やること」、末尾で「次にやること」が1行ずつ表示されます。
3. **末尾の案内どおり、`/02-run` を何度も繰り返します。** これで JSON → `spec/` → trace（対応図）まで進みます。
   ※ 抽出だけの回はモデル **GPT-5.4 mini** でも構いませんが、spec生成・trace生成の回は **GPT-5.4** を使ってください。
4. `/02-run` が「`verify.ps1` の実行と `/03-check` を案内」と表示したら、この手順は完了です。

### 手順4: `verify.ps1` で自動チェックする

1. VS Code のターミナルを開きます（メニュー → Terminal → New Terminal。PowerShell を選択）。
2. 次のように入力して Enter（フォルダ名は自分のIDに合わせて変えてください）。

   ```powershell
   .\.github\skills\detail-design-workflow\scripts\verify.ps1 -RunDir runs\FUNC0123 -SpecDir spec
   ```

3. 結果に `FAIL` が無ければ次へ進めます。`FAIL` が出たら「4. 困ったとき」を読んでください。

### 手順5: `/03-check` で意味を確認する（別チャットで）

1. Copilot Chat で **新しいチャット** を開きます（手順3までとは別のチャットにするのが大切です）。
2. モデルを **GPT-5.4** にし、入力欄に `/03-check` と打って Enter。
3. JSON と `spec/` の内容が食い違っていないかを AI が確認し、`20-check/check-result.md` に `PASS` / `PASS_WITH_WARNINGS` / `FAIL` の結果を残します。

以上で1機能の変換は完了です。別の機能は、手順1からもう一度繰り返してください。

## 4. 困ったとき

- **警告（warnings）が出た**: 変換は止まりません。警告は `runs/<機能ID>/20-check/warnings.md` にまとまります。
  「未レビュー」「EV指摘」などは、人が後で確認するためのメモです。内容を読んで、直したい場合は手順3（`/02-run`）をやり直せば反映されます。
- **`FAIL` で止まった（機械FAIL）**: これは出力が機械的に壊れているサインです（JSONの形が不正、出典が空、など）。
  該当の作業を修正するには、その JSON を作り直すために手順3（`/02-run`）を再実行してください。人の承認待ちで止まることはありません（止まるのは機械FAILのときだけです）。
- **未知のフォーマットと言われた**: 見たことのない設計書の形だと、`/01-setup` は止まらずに「調査モード」で候補を提示し、確認をうながす警告を出します。
  提示された候補が正しいか確認し、必要なら設計書の役割の書き方を担当者に相談してください。
- **設計書の書き方をそろえたい**: `docs/design-doc-request.md`（設計書フォーマットの要望書）を設計チームへ渡してください。対応が進むほど AI の間違いが減ります。
