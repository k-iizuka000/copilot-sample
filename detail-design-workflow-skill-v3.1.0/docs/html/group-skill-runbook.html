導入・入口スキル・日々の手順・モデル割当

SKILL.md（入口）・RUNBOOK.md（日々の手順の正本）・README.md（導入とクイックスタート）・.vscode/settings.json（VS Code設定）をまとめたページ。導入 → 実行の流れ → モデル割当 → 困ったとき、の順に読む。

人間が導入時・実行時に読む /01-setup /02-run verify.ps1 /03-check の実行手順として参照する

まず読むもの

  2. 日々の作業手順（正本）: RUNBOOK.md（このページ #flow-overview）

実行入口（.github/prompts/ の Prompt File を使う）

  • /01-setup — 初回・設計書追加時の棚卸しとルーティング計画
  • /02-run — 次の1タスクを自動選択して実行（反復）
  • /03-check — 意味照合（/02-run とは別チャットで実行）

スコープ外: コード実装・実装計画・テスト生成へは進まない。

導入手順（README.md §2・最初に1回だけ）

  1. .github・.vscode・spec-format の3フォルダを、変換したいリポジトリのルートへコピーする（spec-format は出力形式の正本でプロンプトが参照するため必須。docs はコピー不要）。
  2. コピー先に既存の .vscode/settings.json がある場合は上書きしない。このパッケージの settings.json にある2項目を既存ファイルへ継ぎ足す。
  3. VS Code を再読み込みする（コマンドパレット Ctrl+Shift+P → Reload Window）。
  4. 動作確認: Copilot Chat の入力欄で /01-setup と打ち、候補に出れば準備完了。

.vscode/settings.json の2キー（何のためか）

chat.promptFilesLocationsプロンプトファイルの置き場所（.github/prompts）を Copilot Chat に教え、チャット欄での /01-setup 等の候補表示を有効にする。
json.schemas10-json/ 配下の J-00〜J-90 各JSONにスキーマを紐付け、VS Code 上での形式検証を効かせる（9スキーマ全件。一覧は group-contracts-json.html）。

全体の流れ（RUNBOOK.md）

見方: 上から順に実行する5つの区分。「/02-run を繰り返す」だけは案内が変わるまで何度も回す。

「次はどれをやる？」を人間が考えなくていいように作ってある。同じ /02-run を、案内が「完了」と出るまで繰り返し実行するだけでよい。

初回セットアップ（最初の1回だけ）

  1. 対象リポジトリを VS Code で開く。
  2. run-template/FEATURE-ID フォルダをコピーし、名前を対象の機能ID（例: FUNC0123）に変える。コピー先は runs/ の下（例: runs/FUNC0123/）。フォルダ構成の詳細は group-run-template.html。
  3. コピーした run-request.json を開き、機能ID・機能名・設計書ファイル名・出力先（spec/）を記入して保存する（README では加えて「ID種別」も記入対象。全キーは group-run-template.html#run-request を参照）。
  4. 設計書（Excel）を Copilot が直接読めない場合は、対象シートを CSV または TSV に書き出し、runs/FUNC0123/00-input/ に置く。書き出しは人間が行う前処理で、Prompt の工程ではない。

手順1: /01-setup（設計書の棚卸しとルーティング計画）

  1. VS Code の Copilot チャットを開く（モデル: GPT-5.4。詳細は #models）。
  2. チャット欄で /01-setup と入力して Enter。
  3. 対象の作業フォルダ（例: runs/FUNC0123）を伝える。
  4. Copilot が設計書を1冊ずつ棚卸しし、各シートの役割を判定して、計画ファイル runs/FUNC0123/10-json/J-01-*.json を作る。
  5. Copilot が「次は /02-run を実行」と案内したら、この手順は完了。
  6. 未知のフォーマットが見つかった場合、Copilot は止まらず「調査モード」で候補プロファイルを提示し、確認をうながす警告を出す。内容を人間が見て、必要なら設計書の役割を伝え直す。

手順2: /02-run を繰り返す（次の1タスクを自動実行）

  1. Copilot チャットで /02-run と入力して Enter。
  2. Copilot は毎回、冒頭で「今回やること」を1行宣言してから、次の優先順で最初に該当する1タスクだけを実行する: 設計書の抽出（シート/ブロック → J-* JSON）／spec/ の責務ファイル生成／spec/trace/{機能ID}.md の生成。
  3. Copilot は末尾で「次にやること」を1行案内し、未解消の警告があれば要約表示する。
  4. 案内が「まだ残りがある」内容なら、もう一度 /02-run を入力して Enter。これを、案内が「verify.ps1 の実行と /03-check を案内」に変わるまで繰り返す。
  5. 途中で機械FAIL（JSONが壊れている・出典が無い等）を検出したタスクは実行されず、runs/FUNC0123/20-check/warnings.md に記録されて止まる。人間レビュー待ちでは止まらない。

手順3: verify.ps1（機械チェック）

  1. PowerShell を開く（開き方は資料で2通り示されている: ① Windows のスタートメニューから開く＝RUNBOOKより ② VS Code のターミナル「Terminal → New Terminal」で PowerShell を選択＝READMEより。以降は同じ）。
  2. cd で対象リポジトリのフォルダに移動する（例: cd C:\work\my-repo）。
  3. 次を1行で入力して Enter（FUNC0123 は対象の機能IDに置き換える）: 
    .\.github\skills\detail-design-workflow\scripts\verify.ps1 -RunDir runs\FUNC0123 -SpecDir spec
  4. 画面に OK / WARN / FAIL が日本語で表示される。詳細は runs\FUNC0123\20-check\verify-result.md に出る。
  5. FAIL（機械的に壊れている）が出たら、/02-run をもう一度実行して該当箇所を作り直す。verify が FAIL のまま次へ進まない。WARN だけなら次へ進んでよい。

手順4: /03-check（意味チェック・別チャットで実行）

  1. Copilot チャットの上部で「新しいチャット」を開く（/02-run を回したチャットとは別にする）。理由: 生成時の途中経過（推論や言い訳）を引き継ぐと評価が甘くなるため、入力・成果物・スキーマだけを渡した新しい会話でチェックする。
  2. 新しいチャットで /03-check と入力して Enter（モデル: GPT-5.4）。
  3. 対象の作業フォルダ（例: runs/FUNC0123）を伝える。前提として verify.ps1 が緑（FAILなし）であること。未実行なら先に手順3を行う。
  4. Copilot は意味照合だけを行う（条件・否定・例外・数値・順序が spec/ で失われていないか、創作が無いか、「該当なし」と「未確認」の混同が無いか等）。機械照合は verify.ps1 の担当なので重複してやらない。
  5. 結果は runs/FUNC0123/20-check/check-result.md に PASS / PASS_WITH_WARNINGS / FAIL で出る。FAIL でも Copilot は成果物を直さない。直すときは /02-run を再実行する。

モデル割当（RUNBOOK.md）

工程ごとに使うモデルを決めてある。間違えると手戻りが大きい工程は、軽量モデル（GPT-5.4 mini）だけで完結させない。

工程モデル
/01-setupGPT-5.4
/02-run（シート抽出）GPT-5.4 mini
/02-run（spec生成・trace生成）GPT-5.4
/03-checkGPT-5.4
verify.ps1モデル不使用（PowerShell スクリプト）

人間レビューの推奨タイミング（RUNBOOK.md）

以下は「見ておくと安心」という推奨であって、レビューをしないと先へ進めない仕組みではない（非ブロッキング）。未レビューでも作業は止まらず、気づいた点は warnings.md に残していく。
  • JSON ができた後（/01-setup の J-01、/02-run の抽出 JSON）… 出典やシート分類の判定が妥当か、ざっと確認する。
  • spec/ の Markdown ができた後（/02-run の生成物）… 責務の振り分け・trace の対応表が意図どおりか確認する。
