詳細設計ワークフロー v3.1.0 解説マップ

detail-design-workflow-skill v3.1.0 の入力・処理・出力を図で見せる解説サイトです。まず下の概要とパイプライン図で全体像をつかみ、気になる工程・正本のページへ進んでください。

概要

Excel設計書 → 出典付きJSON → 詳細設計Markdown（spec/）へ、GitHub Copilot が半自動で変換します。毎回同じ命令を繰り返し打つだけで進み、「次は何をすればいいか」を人が考える必要はありません。

入力Excel設計書の CSV/TSV スナップショット
出力spec/ 詳細設計 Markdown + runs/ 作業中間物
スコープ外コード実装・実装計画・テスト生成はしない

用語メモ（README より）

用語意味
Copilot ChatVS Code の右側に出る、AI と会話する欄。ここに /命令 を打って使う。
プロンプト（/01-setup など）あらかじめ用意した命令。チャット欄で / を打つと候補が出る。
run-template1つの機能を変換するための作業フォルダの雛形。コピーして使う。
spec/変換結果（詳細設計Markdown）が入る、最終出力のフォルダ。
runs/変換の作業途中ファイルが入るフォルダ。作業が終われば消してかまわない。
verify.ps1出力が壊れていないかを自動でチェックする PowerShell スクリプト。
プロファイル設計書の種類ごとの読み取り方の定義。役割が書かれていない設計書は、これで役割を推定する。

パイプライン図

見方: 上から下へ実行順。琥珀の点線は人間の操作、それ以外はクリックで各工程ページへ移動できます。

e2j 青=計画 j2m 緑=生成 d00 グレー=機械チェック ev 琥珀=意味照合 human 琥珀枠=人間の操作
人間: 作業フォルダ準備 run-template コピー・CSV/TSV 配置・run-request.json 記入
↓
/01-setup 棚卸し・J-01 計画
↓
/02-run 抽出 → spec生成 → trace生成 ↻ 繰り返し（案内が「完了」と出るまで何度も）
↓
verify.ps1 機械チェック
↓
/03-check 意味照合・別チャットで実行

止まるのは機械FAILのときだけ。人間レビューは非ブロッキング（→ group-rules.html#gates）
