手順（原本の順序のまま）

1 run-request.json を読む 対象機能ID・設計書ファイル一覧・ID種別の宣言を確認する。
2 00-input/ の設計書スナップショットを確認する 生の .xlsx しか無く読めない場合はCSV/TSVの提出を要求し、推測で続行しない。
3 設計書を1冊ずつ棚卸しし、シートの役割を判定する 分類優先順位: ①シート内の役割明記（A1セル等）を最優先 → ②profilesのシート名推定 → ③推定は「推定」とJ-01に記録。
4 未知フォーマットは停止せず調査モードで進む 候補プロファイル案を最大2つ提示し、人間確認を促す警告をwarnings.md（種別:未レビュー）とJ-01のissueに記録する。
5 routingPlan エントリを作る 抽出単位・想定recordType群（ルーティング表の値のみ）・出力先J-*スキーマ・処理状態の初期値を持つ。
6 ID種別を確認する 設計書から判別できない場合は run-request.json の宣言を正とする。
7 J-01 JSON を書き出す runDir/10-json/J-01-{機能ID}.json を1つだけ書き出す。J-01以外は生成しない。

出力

J-01 JSON（routingPlan込み）

何が: シート分類＋抽出計画（routingPlan）を持つ J-01。

どこへ: runDir/10-json/J-01-{機能ID}.json

形式: J-01 スキーマ 準拠。

限定表現: J-01 以外は生成しない。

warnings.md 追記（必要に応じ）

何が: 未レビュー種別の警告（未知フォーマット検出時の候補プロファイル案など）。

どこへ: runDir/20-check/warnings.md

チャット応答（毎回この形で締める）

1. 棚卸し要約（対象冊数・シート数・分類確定/推定/未知の内訳）を数行で報告。

2. 未レビュー・未知フォーマットの警告があれば件数を要約。

3. 「次にやること: /02-run を実行してください」と1行で案内。

停止条件・やらないこと

停止条件（機械FAILのみ）

run-request.json が無い／読めない、または 00-input/ の設計書が1冊も読み取れない場合のみ停止する。

停止しないこと

シートの役割が推定であることや、未知フォーマットの存在では停止しない（警告に記録して進む）。

禁止事項（原本の「〜しない」文）
  • 生の .xlsx しか無く中身を読めない場合は、推測で続行しない。
  • J-01 以外は生成しない。
