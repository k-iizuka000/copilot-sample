# 設計書フォーマットに関するお願い（要望書）

設計チームのみなさまへ。詳細設計の変換作業を、より正確に・より少ない手直しで進めるために、
今後作成・改訂される設計書について、以下のご協力をお願いしたく本書をお送りします。

## はじめに（この依頼の位置づけ）

- これは設計書フォーマットの **一部追加・修正レベル** のお願いです。設計書を全面的に作り直していただく必要はありません。
- 対応をいただく前でも、変換作業は **設計書の見た目から役割を推定する仕組み（プロファイル推定）** で動きます。
  ですので、この依頼への対応を待たずに、いまの設計書のまま使い始めていただけます。
- 下記に対応いただくほど、AI による推定が減り、変換結果の間違いと手直しが着実に減ります。可能な範囲から少しずつで構いません。

以下の各項目には「なぜ必要か（AI の間違いがどう減るか）」を添えています。

## 1. 各シートに「役割」を明記してください

- 各シートの固定セル **A1** に、そのシートの役割を表す「役割タグ」を1つ記入してください。
- 役割タグは次の候補から選んでください（この中の言葉をそのまま書いてください）。

  | 候補 | 候補 | 候補 |
  |---|---|---|
  | レイアウト | 画面項目(Form) | バリデーション |
  | 項目制御 | イベント | メッセージ |
  | 処理記述 | 検索要領 | 更新要領 |
  | DB項目対応 | エンティティ定義(DTO) | DAOレコード定義 |
  | 権限 | コード値 | 共通規約 |
  | 改訂履歴 | その他 | |

- **なぜ必要か**: シートの役割が明記されていれば、AI はシート名から役割を推測せずに済みます。
  推測が外れると、項目が誤ったカテゴリに振り分けられ、後工程の手直しが大きくなります。

## 2. 設計書ファイル名に「ID の種別」が分かる名前を付けてください

- ファイル名を見ただけで、そのID が **機能ID / 画面ID / ジョブID** のどれなのかが分かる命名にしてください。
- **なぜ必要か**: 出力の格納先（画面・処理・バッチ）は ID の種別で決まります。種別が曖昧だと格納先を誤り、
  同じ機能の設計が別々の場所に散らばってしまいます。

## 3. 表形式のシートには、各行に「行ID」の列を1つ足してください

- 表になっているシート（項目一覧・バリデーション一覧など）の各行に、一意な行ID（連番で構いません）を持たせてください。
- **なぜ必要か**: 各仕様が「どの行から来たか」を安定して指し示せるようになります。
  行の追加・削除で位置がずれても出典が保てるため、「出典が分からない」「別の行と取り違える」といった誤りが減ります。

## 4. テーブル間の関連（FK・参照関係）を書く欄を設けてください

- テーブルやエンティティの定義書に、テーブル同士の関連（外部キー・参照関係）を明記する欄を設けてください。
- **なぜ必要か**: ER 図（テーブル関連図）は、設計書に **明記された関連だけ** を根拠に作成します。
  AI が関連を推測して線を引くことはしません。明記がないと関連図に載らず、逆に明記いただければ確実に反映されます。

## 5. 結合セル・非表示の行や列は、できるだけ使わないでください

- セル結合や、行・列の非表示は、可能な範囲で避けてください。データは1セル1値でお願いします。
- **なぜ必要か**: 結合セルや非表示部分は機械での読み取りが不安定になり、値の取りこぼしや位置ずれの原因になります。
  避けていただくことで、読み取り漏れによる誤りが減ります。
