# 00. 全体像と注意事項（最初にこれを読む）

AWS 上にリモート開発環境（EC2 + VS Code Remote-SSH）を構築するための手順書です。
AWS を初めて触る人が、この手順書だけで接続まで到達できることを目標にしています。

## 読む順番

| ファイル | 内容 | 所要時間の目安 |
|---|---|---|
| **00**（本書） | 全体像・用語・危険操作・費用 | 15分（読むだけ） |
| **01** | AWS 側の構築（VPC → 鍵 → ロール → EC2 → 自動停止） | 60〜90分 |
| **02** | ローカル PC の設定（AWS CLI → SSH → VS Code 接続） | 30〜60分 |
| **03** | EC2 の中の環境構築（パッチ・Git・Java・コード持ち込み・Copilot） | 30〜60分 |
| **04** | 日々の使い方・スペック変更・困ったときの対処 | 構築後の日常用 |

> **画面の文言について**: AWS の管理画面は時々デザインが変わります。ボタン名が手順書と完全一致しなくても、近い名前のものを探してください。「何をするための操作か」を各手順に書いてあるので、それを頼りに判断できます。

## 1. 完成図（何を作るのか）

```
【会社 PC】                          【AWS 東京リージョン】
                                     ┌──────────────────────────────┐
 VS Code ──── SSH(暗号化) ────────▶ │ AWS SSM（接続の中継サービス）  │
 （画面表示だけ担当）    インター     └──────────┬───────────────────┘
                        ネット経由              │ EC2側から張った管理回線
 起動.bat                                       ▼
 （朝ダブルクリック）                ┌──────────────────────────────┐
                                    │ EC2 インスタンス（仮想サーバー）│
                                    │  Ubuntu 24.04                 │
                                    │  - VS Code Server（本体処理）  │
                                    │  - Java・ビルド               │
                                    │  - GitHub Copilot             │
                                    │  - 会社のソースコード          │
                                    │  ※外から入る穴（ポート）ゼロ  │
                                    │  ※毎晩21:00に自動停止        │
                                    └──────────────────────────────┘
```

ポイントは3つです。

1. **重い処理は全部 EC2 側で動く**。手元の VS Code は「画面表示とキー入力」だけを担当するので、PC が非力でも軽快に動きます。これは VS Code の Remote-SSH 機能の公式設計です
   - 根拠: [VS Code 公式ドキュメント Remote-SSH](https://code.visualstudio.com/docs/remote/ssh) — 「ソースコード、拡張機能、ターミナル、デバッグはすべてリモートマシン上で実行され、ローカルには UI だけが残る」という構成が図解されています
2. **EC2 には外から入る穴を一切開けない**。接続は AWS の管理サービス SSM を経由し、EC2 側から張ってある管理回線に SSH を相乗りさせます（詳しくは §3）
3. **毎晩 21:00 に自動停止**して課金を止める。朝はダブルクリック1発で起動

## 2. 用語辞典（登場人物の紹介）

手順書に出てくる言葉はこれで全部です。分からなくなったらここに戻ってください。

| 用語 | 何者か |
|---|---|
| **リージョン** | AWS のデータセンターの所在地。今回は「東京（ap-northeast-1）」だけを使う。**画面右上に常に表示されていて、間違ったリージョンで作業すると作ったものが見えなくなる**（§4 参照） |
| **VPC** | AWS 内に作る「自分専用の仮想ネットワーク区画」。マンションの1フロアを借りるイメージ。EC2 はこの中に置く |
| **サブネット** | VPC の中の部屋割り。今回は「パブリックサブネット（インターネットと通信できる部屋）」を1つだけ使う |
| **EC2 / インスタンス** | AWS 上の仮想サーバー（＝借り物のパソコン）。「インスタンス」は EC2 の1台分のこと |
| **インスタンスタイプ** | EC2 のスペックの型番。今回は **m6a.xlarge**（CPU 4個・メモリ 16GB） |
| **AMI** | EC2 の初期状態のひな型（OS 入りのイメージ）。今回は Ubuntu Server 24.04 を選ぶ |
| **EBS** | EC2 に繋がる仮想ハードディスク。今回は 50GB。**EC2 を停止してもここの中身は消えない** |
| **セキュリティグループ** | EC2 の門番（ファイアウォール）。「どこから何の通信を受け入れるか」のルール集。今回は**受け入れルールを空にする**（＝誰も入れない。SSM 経由なので問題ない） |
| **IAM ユーザー** | AWS を操作する「人間用」のアカウント。あなたが持っているもの |
| **IAM ロール** | AWS を操作する「機械用」の許可証。今回は「EC2 が SSM と通信してよい」という許可証を作って EC2 に持たせる |
| **キーペア** | SSH 接続の鍵。公開鍵（EC2 側に置く）と秘密鍵（あなたの PC に置く `.pem` ファイル）のペア。**秘密鍵は再発行できない** |
| **SSM (Systems Manager)** | AWS のサーバー管理サービス。今回は「Session Manager」という機能を接続トンネルとして使う |
| **EventBridge Scheduler** | AWS の目覚まし時計。「毎晩 21:00 に EC2 を停止しろ」という予約を仕込む |
| **AWS CLI** | AWS をコマンドで操作する道具。ローカル PC に入れる（起動スクリプトと SSM 接続に使う） |
| **Session Manager plugin** | AWS CLI の追加部品。SSM のトンネルを PC 側で開くために必要 |

## 3. なぜこの構成なのか（会社メモとの対応）

会社から渡されたメモとこの手順書の対応です。

| 会社メモの記述 | 本手順書での扱い |
|---|---|
| 「PC と EC2 の接続に SSM で接続する必要がある」 | そのまま採用。**SSH（通信方式）を SSM（通り道）に通す**構成。ポートを開けないので安全で、会社のネットワークの IP が変わっても影響を受けない |
| 「SSM 接続を許可するロールを作る」 | 手順書 01 の Step 3。「ロール → エンティティ → ユースケース → ポリシー」というメモの言葉は、この画面の入力項目のこと |
| 「まずは r6a.large を使って」 | **m6a.xlarge に変更（口頭で許可取得済み・2026-08-05）**。理由: Java 開発で足りないのはメモリ（16GB で十分）ではなく CPU コア数。r6a.large（2コア・16GB）→ m6a.xlarge（4コア・16GB）でコア数を倍にし、メモリは同じに保つ |
| （AWS CodeCommit の利用） | **使えない**。CodeCommit は 2024年7月に新規利用の受付を終了した。根拠: [AWS 公式ブログ](https://aws.amazon.com/blogs/devops/how-to-migrate-your-aws-codecommit-repository-to-another-git-provider/) — 冒頭に「CodeCommit は新規顧客の受け入れを終了した」と明記。コードの持ち込みは手順書 03 の方法（リポジトリ丸ごとコピー）で行う |

SSH over SSM が公式にサポートされた方法である根拠: [AWS Systems Manager 公式ドキュメント「セッションを開始する」](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-sessions-start.html) — 「SSH 接続用のセッションを開始する」という節があり、Session Manager のトンネル越しに SSH 接続する手順と前提条件（EC2 側の SSM Agent、`AWS-StartSSHSession` という接続方式の指定）が説明されています。手順書 01・02 はこの内容を初心者向けに展開したものです。

## 4. 🔴 危険操作一覧（作業前に必ず読む）

AWS の画面には「押すと消えるボタン」と「押しても安全なボタン」が同じ場所に並んでいます。ここだけは暗記してください。

### 絶対にやってはいけない

| 操作 | 何が起きるか | どこに出てくるか |
|---|---|---|
| インスタンスの **「終了」（Terminate）** | **EC2 が削除される。ディスクの中身（コード・設定）ごと全部消え、復元できない** | EC2 画面の「インスタンスの状態」メニューの中に「停止」と並んで表示される。**「停止」と「終了」は1行違い** |
| EBS **ボリュームの「削除」** | ディスクの中身が消える | EC2 画面の左メニュー「ボリューム」 |
| アクセスキーを人に見せる・ファイル共有・Git にコミットする | あなたの権限（管理者）で AWS を他人に操作される。**仮想通貨採掘に悪用され数百万円請求される事故が実在する** | 手順書 02 で作る2つの文字列 |

- 「終了」の危険性の根拠: [EC2 公式ドキュメント「インスタンスの終了」](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/terminating-instances.html) — 「終了後にインスタンスに再接続することはできない」「ルートボリュームは既定で削除される」と明記されています
- この手順書では保険として **「終了保護」を有効にして EC2 を作ります**（01 Step 4）。有効の間は「終了」を押してもエラーになります。それでも「保護を解除してから終了」は可能なので、暗記の代わりにはなりません

### やると課金が増える（この手順書では使わない）

| 操作 | 何が起きるか |
|---|---|
| **NAT ゲートウェイ**の作成 | 存在するだけで **1時間ごとに課金**（約 $0.062/時 ≈ 月7千円）。手順書 01 の VPC 作成画面で「なし」を選ぶ場面がある。**絶対に「なし」のまま** |
| **Elastic IP** の確保 | 固定 IP アドレスの予約。今回の構成では不要。確保だけして使わないと課金される |
| インスタンスタイプを大きくしたまま忘れる | 時間単価がそのまま倍々に増える（04 の変更手順に単価表あり） |

### 安全な操作（怖がらなくてよい）

| 操作 | 何が起きるか |
|---|---|
| インスタンスの **「停止」（Stop）** | パソコンのシャットダウンと同じ。**ディスクの中身は全部残る**。CPU 分の課金が止まる。翌日「開始」すれば続きから使える |
| インスタンスの **「再起動」（Reboot）** | パソコンの再起動と同じ。データは消えない |

- 根拠: [EC2 公式ドキュメント「インスタンスの停止と起動」](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/Stop_Start.html) — 「停止中はインスタンスの使用料金は発生しない」「アタッチされた EBS ボリュームのストレージ料金は発生する」と明記。つまり停止中はディスク保管料（月700円程度）だけになります

### リージョンの間違いに注意

画面右上に現在のリージョン（「東京」）が常に表示されています。**これが「バージニア北部」などになっていると、作ったはずの EC2 が画面に出てきません**（消えたのではなく、別の場所を見ている）。「作ったものが見つからない」ときは、まず右上を確認してください。

## 5. 費用の見積もり

為替 150円/$ での概算です。単価の出典: [EC2 オンデマンド料金表](https://aws.amazon.com/jp/ec2/pricing/on-demand/)・[EBS 料金表](https://aws.amazon.com/jp/ebs/pricing/)（いずれも東京リージョンを選択して表示。m6a.xlarge = $0.2232/時 は 2026-08-05 に確認した値）。

| 項目 | 単価 | 月額の目安（平日9時間 × 21日稼働） |
|---|---|---|
| EC2 稼働（m6a.xlarge） | $0.2232/時（約 ¥33/時） | 約 **¥6,300** |
| パブリック IPv4 アドレス | $0.005/時（稼働中のみ） | 約 ¥140 |
| ディスク（EBS gp3 50GB） | 約 $0.096/GB・月 | 約 **¥720**（**停止中もかかる**） |
| **合計** | | **約 ¥7,200/月** |

- IPv4 課金の根拠: [AWS 公式ブログ（2024年発表）](https://aws.amazon.com/jp/blogs/news/new-aws-public-ipv4-address-charge-public-ip-insights/) — 2024年2月からすべてのパブリック IPv4 アドレスに $0.005/時が課金されると告知されたもの。今回の構成では停止中はアドレスが返却されるため、稼働中のみの課金です
- **もし 24時間つけっぱなしにすると約 ¥25,000/月**。毎晩の自動停止（01 Step 6）が効いているかどうかで3倍以上変わります
- 自動停止に使う EventBridge Scheduler は無料枠（月1,400万回の実行まで無料）に収まるため ¥0
