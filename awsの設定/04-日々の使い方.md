# 04. 日々の使い方（構築後の日常リファレンス)

構築（01〜03）が終わったあと、普段見るのはこのファイルだけです。

---

## 1. 毎日の流れ

```
朝:  デスクトップの「EC2起動.bat」をダブルクリック
     ↓ 1〜2分待つ（コーヒーでも入れる）
     VS Code を開く → 左下「><」アイコン → dev-ec2 に接続
     （または「ファイル」→「最近使用した項目」から前回のフォルダを開くだけ）
     ↓
     普通に開発する（保存はこまめに Ctrl+S。または自動保存を ON）
     ↓
夜:  何もしない → 21:00 に自動停止
     早く上がる日は「EC2停止.bat」で手動停止すると、その分課金も止まる
```

- 21:00 をまたいで作業していた場合: 接続が突然切れますが、**保存済みファイルは無事**です。続けるなら「EC2起動.bat」→ 1〜2分 → VS Code で再接続
- 月1回程度、朝の起動直後に EC2 のターミナルで `sudo reboot` を実行してください（セキュリティ更新のうちカーネル分を効かせるため・03 Step 2。1〜2分後に VS Code の「再接続」を押せば戻ります）

## 2. GitBucket へ変更を返す（push したいとき）

**方法A（EC2 から直接）を設定してある場合** — EC2 の VS Code のターミナルで（詳細は 03 Step 6）:

```bash
git push origin ブランチ名
```

**方法B（会社 PC で中継）の場合** — 会社 PC の PowerShell で:

```powershell
cd "C:\path\to\リポジトリ名"
git pull ec2 ブランチ名
git push origin ブランチ名
```

## 3. スペックが足りないと感じたら（インスタンスタイプ変更）

### 判断材料の集め方

「なんとなく遅い」ではなく、まず**何が足りないか**を見ます。EC2 のターミナルで:

```bash
htop
```

- 画面上部の **CPU バー（4本）が全部 100% 近くに張り付いたまま**下がらない → CPU 不足。タイプを上げる価値あり
- **Mem のバーが 16GB 近くまで埋まっている** → メモリ不足（Java 開発では稀ですが、巨大プロジェクトだとあり得ます)
- どちらも余裕があるのに遅い → EC2 のスペックの問題ではない可能性が高い（回線、ローカル PC、プロジェクト設定など。§5 のトラブル表へ）
- `q` キーで htop を抜けられます
- AWS 画面でも見られます: インスタンスを選択 → 「モニタリング」タブ → 「CPU 使用率 (%)」のグラフ。**会社に増強を相談するときは、このグラフのスクリーンショットが説得力のある証拠**になります

### 変更手順（5分・データは消えない）

タイプ変更は「停止 → 変更 → 起動」だけです。ディスクは別部品（EBS）なので**中身はそのまま**です。

1. 「EC2停止.bat」または AWS 画面でインスタンスを**停止**し、「停止済み」になるまで待つ（1〜2分）
2. AWS 画面でインスタンスを選択 → 「**アクション**」→「**インスタンスの設定**」→「**インスタンスタイプを変更**」
3. 新しいタイプを選んで「**適用**」
4. 「インスタンスの状態」→「**開始**」

- 根拠: [EC2 公式ドキュメント「インスタンスタイプを変更する」](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-resize.html) — 「インスタンスを停止し、インスタンスタイプを変更して、再起動する」という手順が公式に案内されています

### タイプの候補と料金（東京・概算 150円/$）

| タイプ | CPU / メモリ | 時間単価 | 月額目安（9h×21日） | 用途 |
|---|---|---|---|---|
| m6a.large | 2 / 8GB | 約 ¥17 | 約 ¥3,200 | 想定よりずっと軽かった場合の節約先 |
| **m6a.xlarge（現在）** | **4 / 16GB** | **約 ¥33** | **約 ¥6,300** | 開始スペック |
| m6a.2xlarge | 8 / 32GB | 約 ¥67 | 約 ¥12,600 | ビルドが遅くて我慢ならない場合 |

- 単価の正確な値は [EC2 オンデマンド料金表](https://aws.amazon.com/jp/ec2/pricing/on-demand/)（リージョンを「東京」にして確認）が正です
- ⚠️ 上げたら上げっぱなしにせず、月末に「そのスペックが本当に要ったか」を htop の記憶で振り返るのがおすすめです

### ディスクが足りないとき（EBS 拡張・データは消えない）

1. AWS 画面 → EC2 → 左メニュー「**ボリューム**」→ 対象（50GB のもの）を選択 → 「アクション」→「**ボリュームを変更**」→ サイズを例えば `100` に → 「変更」
2. EC2 を再起動（インスタンスの状態 → 再起動）。Ubuntu が起動時に自動でディスク領域を広げます
3. EC2 のターミナルで `df -h /` を実行し、サイズが増えたことを確認
- ⚠️ **拡張はできますが縮小はできません**（小さくするには作り直しが必要）。増やしすぎ注意
- 根拠: [EBS 公式ドキュメント「ボリュームの変更」](https://docs.aws.amazon.com/ebs/latest/userguide/ebs-modify-volume.html) — 使用中のまま拡張できること、縮小はできないことが記載されています

## 4. 料金の確認方法（月1回見る習慣に）

1. AWS 画面の検索窓に「**請求**」→ 「Billing and Cost Management」を開く
2. 「請求書」で今月の金額を確認。**目安の ¥7,200/月（$50 弱）から大きく外れていたら何かがおかしい**
3. よくある原因: 自動停止が失敗している（→ EventBridge のスケジュールが「有効」か確認）／タイプを上げたまま忘れている／NAT ゲートウェイなど想定外のリソースがある

## 5. 困ったときの対処表

### 接続まわり

| 症状 | 原因の可能性が高い順に |
|---|---|
| VS Code / ssh が繋がらない | ① **EC2 が停止している**（朝の起動 bat を忘れていないか。AWS 画面で「実行中」か確認）② 起動直後すぎる（1〜2分待つ）③ 会社のネットワークが変わった（02 付録のプロキシ確認） |
| `UNPROTECTED PRIVATE KEY FILE` エラー | 鍵の権限が緩んだ。02 Step 4 の icacls 2行を再実行 |
| `TargetNotConnected` エラー | EC2 停止中／起動直後。上と同じ。まれに SSM 側の一時的な問題（5分後に再試行） |
| 昨日まで繋がったのに急にダメ | AWS 画面 → インスタンス → 「接続」→「セッションマネージャー」を試す。**それが通るなら AWS 側は正常＝原因はローカル PC 側**（02 の完了チェックを上から再確認）。通らないなら EC2/AWS 側（再起動を試す） |
| VS Code の接続が途中で固まる・壊れた | F1 →「Remote-SSH: Kill VS Code Server on Host」を実行して再接続。直らなければ ssh で入って `rm -rf ~/.vscode-server` → 再接続（VS Code Server が自動再インストールされる。**コードには影響なし**） |
| 21:00 に切断された | 仕様どおり（01 Step 6）。起動 bat → 再接続で続きから |

### 開発まわり

| 症状 | 対処 |
|---|---|
| Copilot の補完が出ない | 右下の Copilot アイコンを確認 → サインイン切れなら再サインイン（03 Step 7）。EC2 からインターネットに出られているかは `curl -sI https://github.com` で確認（`HTTP/2 200` 等が返れば正常） |
| Java の補完・エラー表示が効かない | 初回解析中（右下の進行表示を待つ）。直らなければ F1 →「Java: Clean Java Language Server Workspace」 |
| ビルドが異常に遅い | `htop` で CPU を確認（§3）。4コア張り付きが常態なら m6a.2xlarge を検討 |
| `git status` で全ファイルが変更扱い | 改行コード問題。`git config core.autocrlf input` を実行（03 Step 5) |
| EC2 での `git push` が `Connection refused` | 方法A の通り道は **VS Code で EC2 に繋いでいる間だけ**有効。VS Code で接続してから再実行（03 Step 6）。接続済みでも直らないときは、一度切って繋ぎ直す（SSH 設定は接続時に読まれる） |
| ディスクフル（No space left on device） | `df -h /` で確認 → §3 のディスク拡張 |

### AWS 画面での操作に迷ったら（再掲・00 §4）

- **「停止」は安全**（シャットダウン。データは残る）
- **「終了」は削除**（データごと消える。終了保護を入れてあるが、過信しない）
- 画面にインスタンスが見えない → **右上のリージョンが「東京」か確認**
