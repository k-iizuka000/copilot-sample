# 人間のアクション一覧（v3.2.0）

このパッケージで**人間が手を動かす必要があるもの**だけを集めた一覧。
「どのファイルを見て・何をするか」で書いてある。ファイル全体の意味は [file-inventory.html](./file-inventory.html) を参照。

## A. 導入時（リポジトリごとに1回だけ）

| # | いつ | 見るもの | やること |
|---|---|---|---|
| A-1 | 最初 | [README.md](../README.md) の「2. 導入手順」 | `.github`・`.vscode`・`spec-format` の3フォルダを対象リポジトリのルートへコピーする |
| A-2 | A-1 の直後 | `.vscode/settings.json` | 既存の settings.json がある場合は上書きせず、`chat.promptFilesLocations` と `json.schemas` の2項目を継ぎ足す |
| A-3 | A-2 の直後 | VS Code | `Reload Window` を実行し、チャット欄で `/01-setup` が候補に出ることを確認する |

## B. 設計チームへの依頼（1回＋更新時）

| # | いつ | 見るもの | やること |
|---|---|---|---|
| B-1 | 導入後なるべく早く | [design-doc-request.md](./design-doc-request.md)（要望書） | 設計チームへ渡し、A1 役割タグ・命名規約・行ID・関連欄・結合セル回避への対応を依頼する |
| B-2 | 設計書種別の正式名称が確定したとき | 要望書の第2項（種別語彙の表） | 暫定3語（画面設計書/機能設計書/DB設計書）を正式名称に更新する（[spec-v3.2.0.md](./spec-v3.2.0.md) の未確定事項も消し込む） |

## C. 1機能を変換するとき（毎回）

| # | いつ | 見るもの | やること |
|---|---|---|---|
| C-1 | 変換の前 | 設計書の Excel | ファイル名を命名規約 `{設計書種別}_{ID}_{機能名}.xlsx` に合わせる（生の .xlsx のまま。CSV/TSV 書き出しは不要） |
| C-2 | 変換の開始 | Copilot Chat（モデル: GPT-5.4） | `/01-setup` を実行し、Excel のパスと出力先（既定 `spec/`）を伝える |
| C-3 | 「空欄があります」と案内されたときだけ | `runs/{ID}/run-request.json` | 空欄を埋める。**featureId（ID）の空欄だけは埋めるまで先に進まない**（埋めたら `/01-setup` を再実行）。それ以外の空欄は後埋めでよい |
| C-4 | セットアップ完了後 | Copilot Chat | `/02-run` を、案内が「verify.ps1 と /03-check へ」に変わるまで繰り返す |
| C-5 | /02-run 完了後 | ターミナル（PowerShell） | `verify.ps1 -RunDir runs\{ID} -SpecDir spec` を実行し、FAIL が無いことを確認する（FAIL なら `/02-run` を再実行） |
| C-6 | verify が緑になったら | Copilot Chat（**新しいチャット**） | `/03-check` を実行し、`20-check/check-result.md` の判定を確認する（FAIL なら `/02-run` を再実行） |
| C-7 | 変換の途中・完了後 | `runs/{ID}/20-check/warnings.md` | 未レビュー・EV指摘・矛盾検出の警告を確認し、対応したら状態を更新する |

## D. 判断が必要になったとき（都度）

| # | きっかけ | 見るもの | やること |
|---|---|---|---|
| D-1 | 「Excel が読み取れない」と停止した | チャットに表示された原因 | 破損・保護ビュー・パスワード等を解除して `/01-setup` を再実行する |
| D-2 | 未知フォーマット（調査モード）の警告が出た | `warnings.md` と提示された候補プロファイル | 候補が正しいか判断する。必要なら設計書側の役割タグ（A1）の記入を設計チームへ依頼する |
| D-3 | 矛盾検出（両論併記）の警告が出た | `warnings.md` と該当の spec/ ファイル | どちらの記述が正か判断し、`/02-run` の再実行で反映させる |

## 対象外（人間がやらなくてよくなったこと・v3.1.0 との違い）

- ~~run-template を手でコピーして runs/ を作る~~ → `/01-setup` が自動で作る
- ~~run-request.json を手で記入する~~ → ファイル名から自動生成（空欄の後埋めだけ人間）
- ~~Excel を CSV/TSV に書き出して 00-input/ に置く~~ → 生の .xlsx を渡すだけ
