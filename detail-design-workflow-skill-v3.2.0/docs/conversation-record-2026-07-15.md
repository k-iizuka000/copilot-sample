# 会話記録（2026-07-15）— v3.2.0 の認識合わせ

**位置づけ**: v3.2.0 の変更に至った認識合わせ（インタビュー）の記録。決定内容の正本は [spec-v3.2.0.md](./spec-v3.2.0.md)。本書は「なぜそう決めたか」を後から追うための経緯記録。

## 発端

- オーナーが v3.1.0 のセットアップを試したところ、GPT（Copilot）から「セットアップの時に JSON が必須です」と言われた。
- 調査の結果、これは 01-setup.prompt.md の仕様どおりの挙動（run-request.json が無ければ停止）であることを確認。
- ただしオーナーの完成イメージは「インプットの Excel・作業ディレクトリ・出力パスを渡して実行するだけ」であり、v3.1.0 の設計（雛形の手動コピー・run-request.json の手書き・CSV/TSV の書き出し）はこのイメージと食い違っていた。

## オーナーの要望（原文の要旨）

1. Excel 形式の設計書を Copilot に渡し、Copilot がマークダウン形式の詳細設計書に落とし込む流れにしたい。
2. 設計書フォーマットは修正可能なので、要望書（design-doc-request.md）に合わせて修正する。
3. CSV や TSV への書き出しは行わない。生のままの Excel を渡す。run-request の記入も含めて、Excel をそのまま渡せば対応できるようにする。
4. ユーザー側の作業は「出力パス」と「インプットの Excel」を渡すだけ。あとは実行し続ければ漏れなくすべて完了する仕様にする。
5. 最終的には、最初の Excel とコマンドを渡すだけで（丸投げするだけで）スペックファイルが全部できるようにする。
6. 認識合わせの結果は仕様としてドキュメントに出力する。会話自体も別ドキュメントに残す。
7. 全ファイルの意味が分かる一覧資料（HTML は分かりやすければよい）と、人間がアクションを起こす必要があるものの一覧を別で用意する。

## インタビューでの決定（質問 → オーナー回答）

| # | 質問 | 回答 | 反映 |
|---|---|---|---|
| 1 | 生 Excel の内部処理方式（スクリプト自動変換 か 直接読み か） | 「xlsx を読めている。何かのコマンドを使っているかも」（現場実測） | Copilot が直接読む（必要なら Agent の手段でコマンド利用可）。人間の変換作業なし |
| 2 | run-request.json の ID・機能名の出所 | ファイル名から取得。要望書とリンク。取得できなければ空白、最後にユーザーが追記 | 命名規約からの自動生成＋空欄運用 |
| 3 | 入力の単位 | まずは一冊ずつ。精度が安定したら機能単位でまとめて投げる | 1回1冊。まとめ投げは将来拡張 |
| 4 | 教材（入力→出力ペア）を残す設計にするか | そのまま（残さない） | fixture の仕組みは追加しない |
| 5 | パッケージの更新方法 | v3.2.0 新フォルダ | v3.1.0 は変更せず並置 |
| 6 | xlsx が読み取れなかったときの挙動 | 原因を報告して停止 | 停止条件に明記。CSV/TSV の提出要求は廃止 |
| 7 | 空欄時の扱い | ファイルは追加しない。run-request を空白にして「空白があるから埋めて」と伝えればOK | featureId のみ停止・他は伝えて続行 |
| 8 | 命名規約の形 | `{設計書種別}_{機能ID（バッチ）/画面ID（画面機能=機能ID+2桁）}_{機能名}` | 要望書第2項に反映 |
| 9 | ID の実形式 | 判別可能。バッチ = `ab12`、画面 = `ab1234` | 桁数（英2+数2 / 英2+数4）で機械判定 |
| 10 | 設計書種別の語彙 | 別にあるが、まだ名称を全て把握できていない | 暫定3語で開始、確定後に要望書を更新（未確定事項に記録） |
| 11 | 空欄時の停止範囲の確認 | 「ID のみ停止・他は続行」の解釈で OK | 01-setup の空欄ゲートに反映 |
| 12 | 新規文書の置き場所 | 全部 v3.2.0 の docs/ | 本書・仕様書・一覧・アクション一覧を docs/ に配置 |

## 補足（AI 側から提示し、オーナーが暗黙に了承した設計詳細）

- Excel 原本は変更せず、runs/{ID}/00-input/ へコピーしたものを以後の読み取りの正とする（出典の安定のため）。
- ID が取れないまま停止した場合の作業フォルダは Excel ファイル名（拡張子抜き）で仮置きし、featureId 確定後の再実行で runs/{featureId}/ に揃える。
- /02-run・/03-check の runDir は未指定なら自動特定（runs/ 直下に run-request.json を持つフォルダが1つだけならそれ）。
