verify.ps1 機械照合スクリプト 機械チェック

原本: .github/skills/detail-design-workflow/scripts/verify.ps1

verify.ps1 は J-* JSON と spec/ の Markdown を突き合わせ、機械的に判定できる壊れ方だけを検出するPowerShellスクリプト（意味照合はしない）。図は7チェックを手順として上から読む。

サマリー

いつ実行するか（RUNBOOKより） /02-run の案内が「verify.ps1 の実行と /03-check を案内」に変わったら、PowerShell から手動で実行する。
使うモデル（RUNBOOKより） モデル不使用（PowerShell スクリプト）
前工程 → この工程 → 後工程 /02-run → verify.ps1 → /03-check

入力

前提: -RunDir と -SpecDir が実在するディレクトリでなければ、検査を開始せずに終了する（exit 1）。

実行パラメータ（param ブロック）

パラメータ渡すもの（原本の説明文）必須
-RunDir 対象 run のルート（例: runs/FUNC0123）。配下に 10-json/ と 20-check/ を持つ。 必須
-SpecDir 最終出力の spec/ ルート（例: spec）。front/back/batch/db/common/rules/trace を持つ。 必須
-Report 指定すると、レコード単位の詳細（各 recordId の出現 spec ファイル一覧）もコンソールへ出力する。既定は要約表示のみ。いずれの場合も verify-result.md / reverse-map.md は必ず生成する。 任意（switch）

参照ファイル（判定ロジックが前提とするコンテキスト）

verify.ps1 はこれらのファイルを実行時に読み込むのではなく、判定ロジック内に同内容のミラー（$Routing / $ValidLayers）を保持する（原本コメントより）。正本が変わった場合は両方の更新が必要。

spec-format/routing-table.md

recordType→出力先ルーティング表の正本。$Routing はこの正本の機械照合用ミラー。

→ group-spec-format.html#routing-table
copilot-instructions.md（共通ルール）

layers の enum の正本（JSON出力節）。$ValidLayers はこの正本のミラー。

→ group-rules.html#json-rules

手順（7チェック）

1 JSON構造チェック 必須キー・recordId一意性・recordType/layersのenum妥当性を確認する（逸脱はFAIL）。
2 ルーティング整合チェック 各レコードの責務（recordType）に対応するspec/ファイルの有無を確認する（WARN）。
3 トレース照合チェック 全recordIdがspec/配下（trace含む）に出現するか照合する（欠落はFAIL）。
4 リンク実在チェック spec/内の相対リンクの解決先が実在するか確認する（リンク切れはWARN）。
5 lintチェック front-matter必須キー5種と仕様表の必須列（Record ID・出典）を確認する（WARN）。
6 矛盾検出チェック（db/ 型・桁） db/の同一カラム物理名に型・桁の矛盾がないか検出する（矛盾検出、WARN）。
7 逆引きマップ生成 recordId→specファイル、テーブル→機能IDの対応表をreverse-map.mdへ出力する。

出力

-Report の指定有無によらず、実行のたびに必ず生成する。

recordId→spec ファイルの対応表、テーブル物理名→機能ID の対応表。

どこへ: RunDir/20-check/reverse-map.md

verify.ps1 が自動生成。手で編集しない（再実行で上書きされる）。実行のたびに必ず生成する。

warnings.md（追記）

未解消の FAIL / WARN の一覧。種別は「機械FAIL」（Severity=FAIL）「機械WARN」（それ以外のWARN）「矛盾検出」（6.矛盾検出チェック由来のみ）。

どこへ: RunDir/20-check/warnings.md（無ければ T-warnings 形式で新規作成）

同一内容が未解消で既存にあれば重複追記しない。追記対象は FAIL/WARN のみ（OK は追記しない）。

コンソール出力（結果サマリ＋判定）

OK/WARN/FAILの件数サマリと、末尾の判定メッセージを表示する:

  • FAILあり:「判定: FAIL（機械的な破損が N 件）。/02-run を再実行して修正してください。」
  • FAILなし・WARNあり:「判定: OK（WARN N 件は非ブロッキング。warnings.md と /03-check で確認してください）。」
  • FAILなし・WARNなし:「判定: OK（機械照合クリア）。次は /03-check（別チャット）で意味照合を行ってください。」

詳細レポート（-Report 指定時のみ）

recordId ごとの出現 spec ファイル一覧をコンソールへ追加表示する（既定では要約のみ）。

FAIL と WARN の区別:
FAIL = 機械的に壊れている（JSONパース不能・必須キー欠落・recordId重複・enum逸脱・トレース欠落）。1件でもあれば終了コード1。
WARN = 人間の判断に委ねる（ルーティング未生成・リンク切れ・lint指摘・矛盾検出）。WARNのみなら終了コード0（OK扱い）。

停止条件・やらないこと

  • -RunDir が見つからない: エラーメッセージを表示して終了する（exit 1）。検査は開始しない。
  • -SpecDir が見つからない: エラーメッセージを表示して終了する（exit 1）。検査は開始しない。
  • FAIL が1件でもあれば終了コード1（「/02-run を再実行して修正してください」と案内）。FAILが解消するまで次工程（/03-check）へは進まない（RUNBOOKより）。
  • WARN のみ（FAILなし）なら終了コード0（OK扱い）。次工程へ進んでよい。
  • 意味照合（条件・否定・例外の欠落など）は行わない。それは /03-check（Copilot側）の責務。
  • PowerShell 5.1 互換・追加インストール不要（Windows標準機能のみを使用）。
  • 日本語のファイル名は扱わない前提（spec/ 配下のファイル名は ASCII）。
  • reverse-map.md は verify.ps1 が自動生成する。手で編集しない（再実行で上書きされる）。
人間レビューでは止まらない: verify.ps1 自体に人間レビューのゲートは無い。WARN は非ブロッキングで、warnings.md と /03-check で確認する（RUNBOOKより）。
