J-* JSONスキーマ契約

中間層 JSON（J-00〜J-90）9本の役割・主要キー・recordType と、どの工程が書き・どの工程が読むかを一覧します。フィールドの全量は各スキーマファイルを直接参照してください。

/01-setup /02-run verify.ps1 /03-check

全工程がこの契約群を入出力の形式として参照します。詳細な書く/読むの対応は各カード下部を参照してください。

J-00 contracts/json/J-00.schema.json

役割: 共通定義（Record ID・出典・issue・アセット・recordBase）。他の J-* スキーマが $ref で参照する共有型で、単体では JSON として出力されない。

主要キー（$defs）: recordId / scope / layers / evidenceState / evidenceType / sourceRef / sourceRefs / runInfo / documentRef / issue / assetRef / recordBase

主な enum: scope = individual / common / shared_master、evidenceState = explicit / derived / ambiguous

書く: なし（共通型のみ） 読む: J-01〜J-90 全スキーマが参照

J-01 contracts/json/J-01.schema.json

役割: 文書マニフェスト（シート分類＋抽出計画 routingPlan）。

主要トップレベルキー: contractId / schemaVersion / profileId / run / document / issues / assets / sheets / routingPlan（必須: contractId, schemaVersion, profileId, document, sheets, routingPlan）

補足: routingPlan の1エントリ = 1抽出単位 = 10-json/ 内の出力ファイル1個と1対1対応。/02-run はそのファイルの実在で未処理判定する（ステートレス）。

主な enum: sheets[].role = metadata / extract / asset / ignore_candidate / reference_only / unknown、matchSource = role_tag / sheet_name_match / inferred / manual / unknown（role_tag が最優先）、routingPlan[].outputContract = J-10 / J-11 / J-20 / J-30 / J-40 / J-60

書く: /01-setup 読む: /02-run（タスク選択・抽出計画） 読む: verify.ps1 読む: /03-check

書く: —（判定・findings の構造契約） 読む: /03-check（構造契約として従う）

v2.1.0 からの軽量化点

見方: CONTRACT-INDEX.md に記載された5項目をそのまま列挙しています。

  • recordBase から hiddenRow / hiddenColumn / locator / sourceUnitId と coverage / summary の数え上げフィールドを削除（網羅性検査は verify.ps1 に委譲）。
  • additionalProperties:false はトップレベルと各レコード（recordBase）にのみ残し、facts など深い階層では外す（mini のスキーマ逸脱で全停止させない）。
  • J-90 の result 別 allOf 強制（PASS 時カウント0強制等）と metrics 数え上げを撤去し、result + findings の単純なリストにした。
  • J-30 に entity_relation（leftTable / rightTable / cardinality / basis / description）を新設。設計書に明記された関連または JOIN 由来のみ（AI 推測禁止）。
  • 出典 sourceRef は { workbook, sheet, range, displayedValue, formula, evidenceType } に軽量化。
