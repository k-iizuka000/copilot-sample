/02-run 次の1タスクを自動実行 生成

原本: .github/prompts/02-run.prompt.md

現在の状態（J-01・抽出済み J-*・生成済み spec/）を見て「次にやるべき1タスク」を自分で選び、1つだけ実行するプロンプト。 案内が「完了」に変わるまで、利用者は同じ /02-run を繰り返し呼ぶだけでよい。下の「処理フロー」で優先順1〜5のどれが選ばれるかを確認する。

サマリー

いつ実行するか（frontmatter description より） 次の1タスクを自動選択して1つだけ実行する。抽出→spec生成→trace生成まで、同じコマンドを繰り返し呼ぶ。 案内が「verify.ps1 の実行と /03-check を案内」に変わるまで繰り返す（RUNBOOK 手順2 より）。
使うモデル（RUNBOOK モデル割当表より） 抽出（ステップ2・シート抽出）: GPT-5.4 mini でよい／spec生成・trace生成（ステップ3・4）: GPT-5.4（手戻りが大きいため mini だけで完結させない）。
前工程 → この工程 → 後工程 /01-setup → /02-run（案内が変わるまで繰り返し） → verify.ps1

次の1タスク選択（原本の優先順のまま）

1 J-01 の有無を確認する 無ければ実行しない（案内のみ・data-writes 空）。
2 未処理の抽出単位を最初の1つだけ抽出する 1シート／1論理ブロックのみ読み、routingPlan が指定する J-* スキーマに従って書き出す（recordId・recordType・layers・sourceRefs 必須。設計・推測はしない）。
3 未生成の spec/ 責務ファイルを1つだけ生成する 全抽出済みが条件。ルーティング表の行順→ID順で最初の1つが対象（詳細は下の「spec 生成の要点」）。
4 trace（specDir/trace/{機能ID}.md）を1つ生成する spec/ 生成済みが条件。T-trace.template.md に従い、クラス図・設計→実装対応表・ER断片・消費マトリクス抜粋を作る。
5 すべて完了していれば案内して終了する 実行しない（次工程への案内のみ・data-writes 空）。

spec 生成の要点（手順3の詳細）

抽出済み J-* の各レコードを、ルーティング表の recordType→出力先で振り分ける。出力先が未生成の責務ファイルのうち、ルーティング表の行順→ID順で最初の1つを対象にする。

対応する Markdown テンプレート（T-items / T-validation / T-methods / T-queries / T-db-table 等）を使う。→ group-templates-markdown.html

front-matter 必須キー（id / generatedFrom / generatedAt / model / provisional）を埋める。

仕様行の表には「Record ID」列と「出典」列を必須で置く。JSON に無い仕様を書かない（創作禁止）。

共通仕様は複製せず、spec/rules/ または spec/common/ へのリンクで参照する。

共有領域（db/ common/ rules/）で既存記述と矛盾する内容を検出したら、上書きしない。両論併記のうえ warnings.md（種別: 矛盾検出）に記録し、人間の判断に委ねる。

出力

J-* JSON（抽出出力）

どこへ: runDir/10-json/。routingPlan が指定する J-* スキーマ準拠（→ group-contracts-json.html）。recordId・recordType・layers・1件以上の sourceRefs を必須で付ける。

spec/ 責務ファイル

どこへ: specDir 配下（ルーティング表の出力先。→ group-spec-format.html#routing-table）。1回の実行で未生成の1ファイルだけを生成する。

spec/trace/{機能ID}.md

どこへ: specDir/trace/。T-trace.template.md 準拠（→ group-templates-markdown.html）。クラス図・設計→実装対応表・ER断片・消費マトリクス抜粋。

warnings.md 追記

どこへ: runDir/20-check/warnings.md。種別: 機械FAIL（4条件検出時）／矛盾検出（共有領域の既存記述と矛盾時）。

実行結果報告（チャット応答）

生成／更新したファイルと件数を数行で報告する（末尾にやること (a)）。

次にやること案内（チャット応答）

残タスクの種類、または /03-check への誘導を1行で案内する（末尾にやること (b)）。

warnings 要約表示（チャット応答）

未解消警告を要約表示する。例:「未レビューのまま進行中 2件」「EV指摘が未修正 1件」「矛盾検出 1件」（末尾にやること (c)）。

停止条件・やらないこと

停止条件（機械FAILのみ・後続タスクを実行せず warnings.md に記録して終了）
  • JSON がパース不能
  • レコードの sourceRefs が空（出典欠落）
  • routingPlan に無いシート／ブロックを参照している
  • recordId が重複している
禁止事項（〜しない）
  • 各レコードに recordId・recordType・layers・1件以上の sourceRefs を付ける際、設計・推測はしない
  • JSON に無い仕様を書かない（創作禁止）
  • 共通仕様は複製せず、spec/rules/ または spec/common/ へのリンクで参照する（複製しない）
  • 共有領域（db/ common/ rules/）で既存記述と矛盾する内容を検出しても、上書きしない
人間レビューの有無では止まらない

未レビューは警告として表示するだけで先へ進む（原本のまま）。
