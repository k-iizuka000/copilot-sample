/03-check 意味照合 意味照合

原本: .github/prompts/03-check.prompt.md
J-* JSON と生成済み spec/ Markdown を突き合わせ、意味の欠落・創作・「該当なし/未確認」混同・basis妥当性を評価する意味照合専用プロンプト（機械照合は verify.ps1 の責務で重複しない）。 見方: 中央の手順カードをクリックすると使う入力が点灯する。

サマリー

いつ実行するか（frontmatter description） J-* JSON と spec/ Markdown の意味照合（欠落・創作・「該当なし/未確認」混同・basis 妥当性）を評価する。02-run とは別チャットで実行する。
使うモデル GPT-5.4（原本frontmatter指定。RUNBOOKモデル割当表と一致）
前工程 → この工程 → 後工程 verify.ps1 → /03-check → 人間が確認（FAILなら /02-run へ戻る）

入力

前提（満たさなければ評価しない）

runDir/20-check/verify-result.md が存在し、verify.ps1 の結果が OK（機械照合が緑）であること。 未実行、または FAIL の場合は評価に入らず、「先に verify.ps1（scripts/verify.ps1 -RunDir <runDir> -SpecDir <specDir>）を実行してください」と案内して終了する。

役割

意味照合だけを行う。spec/ Markdown を修正しない（修正は /02-run の再実行で行う）。

別チャットで実行する

/02-run とは別のチャットで実行する（評価者を生成者から分ける）。理由: 生成時の途中経過（推論や言い訳）を引き継ぐと評価が甘くなるため、入力・成果物・スキーマだけを渡した新しい会話でチェックする（RUNBOOK手順4より）。

パラメータ渡すもの（原本の説明文）必須
runDir 作業ディレクトリ（例 runs/ab1234）。未指定なら自動特定 未指定可（自動特定）
specDir 最終出力ツリー。既定は run-request.json の outputSpecRoot（無ければ spec/） 任意（既定: run-request.json の outputSpecRoot、無ければ spec/）

runDir が未指定（空欄）の場合の自動特定は /02-run と同じ規則に従う（runs/ 直下で run-request.json を持つフォルダが1つだけならそれ。複数なら選択を求める）。

検査項目（原本の順序のまま）＋結果の書き出し

1 欠落が無いか確認する J-* JSON の条件・否定・例外・数値・順序が spec/ Markdown で失われていないか。
2 創作が無いか確認する spec/ にだけ存在する仕様が無いか。JSON に根拠が無い記述はすべて指摘する。
3 「該当なし」と「未確認」の混同が無いか確認する 「該当なし」（=[]）と「未確認」（=null）の混同が無いか。
4 entity_relation の basis 妥当性を確認する explicit→出典(sourceRefs)実在／derived_join→導出元実在／どちらでもないAI推測の関連（推測線は禁止）が無いか。
5 結果を書き出す 判定（PASS/PASS_WITH_WARNINGS/FAIL）とfindings表をcheck-result.mdに書く。findingsはwarnings.md（種別:EV指摘）にも追記する。

PASS: 欠落・創作・混同・basis不正がいずれも無い。／ PASS_WITH_WARNINGS: blockingでない指摘のみが残る。／ FAIL: 欠落・創作・出典欠落・basis不正・矛盾のいずれかがある。

チャット応答

判定・findings件数・出力先を簡潔に報告し、FAILがあれば「修正は /02-run を再実行してください」と1行で案内する。

停止条件・やらないこと

評価に入らない条件

verify-result.md が無い（未実行）、または verify.ps1 の結果が FAIL の場合は評価に入らず、「先に verify.ps1 を実行してください」と案内して終了する。

禁止事項（原本の「〜しない」文）
  • 機械照合（構造・件数・リンク実在など）は verify.ps1 の責務なので、ここでは重複してやらない。
  • spec/ Markdown を修正しない（修正は /02-run の再実行で行う）。
  • FAIL でも成果物（spec/）は修正しない。判定と findings を残すだけにする。
  • AI 推測による entity_relation（推測線）は禁止。basis が explicit / derived_join のどちらにも該当しない関連は指摘する。

停止条件・ゲートの共通の考え方は group-rules.html#gates を参照。
