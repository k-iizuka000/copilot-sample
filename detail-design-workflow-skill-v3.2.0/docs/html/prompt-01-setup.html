手順（原本の順序のまま）

1 Excel を直接受け入れる 生の .xlsx を読み、破損・保護ビュー・パスワード付き等で読めなければ停止する。
2 ファイル名を解釈する 命名規約から設計書種別・ID・機能名を取得し、IDの桁数で種別を判定する。
3 作業フォルダを用意し原本をコピーする 分類優先順位: ①シート内の役割明記（A1セル等）を最優先 → ②profilesのシート名推定 → ③推定は「推定」とJ-01に記録。
4 run-request.json を生成・更新する 取得値で自動生成し、既存なら既存記載を正として設計書を追記する。
5 featureId の空欄ゲートを確認する featureId のみ停止し、他の空欄は伝えて続行する。
6 シートを1枚ずつ棚卸しする 役割明記を優先し、無ければprofilesで推定してJ-01に記録する。
7未知フォーマットを調査モードで扱う候補を最大2つ提示し、警告とJ-01 issueに記録する。
8routingPlan エントリを作る抽出単位・recordType群・出力先スキーマ・初期状態を記録する。
9ID種別を確定する設計書から判別できない場合は run-request.json の宣言を正とする。
7 J-01 JSON を書き出す runs/{ID}/10-json/J-01-{ID}.json を1つだけ書き出す。

出力

J-01 JSON（routingPlan込み）

何が: シート分類＋抽出計画（routingPlan）を持つ J-01。

どこへ: runs/{ID}/10-json/J-01-{ID}.json

形式: J-01 スキーマ 準拠。

限定表現: J-01 以外は生成しない。

warnings.md 追記（必要に応じ）

何が: 未レビュー種別の警告（未知フォーマット検出時の候補プロファイル案など）。

どこへ: runDir/20-check/warnings.md

チャット応答（毎回この形で締める）

1. 受け入れ結果（作業フォルダ・run-request.json の生成/更新・空欄項目）を報告。

2. 棚卸し要約（対象冊数・シート数・確定/推定/未知）を報告。

3. 警告件数を要約し、最後に「次にやること: /02-run を実行してください」と案内。

停止条件・やらないこと

停止条件（機械FAILのみ）

Excel が読み取れない場合、または run-request.json の featureId が空欄の場合のみ停止する。

停止しないこと

シートの役割が推定であることや、未知フォーマットの存在では停止しない（警告に記録して進む）。

禁止事項（原本の「〜しない」文）
  • 生の .xlsx しか無く中身を読めない場合は、推測で続行しない。
  • J-01 以外は生成しない。
