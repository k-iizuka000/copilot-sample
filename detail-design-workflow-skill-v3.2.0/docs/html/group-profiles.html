設計書プロファイル

/01-setup がシートの役割を推定するときに読む7本のプロファイルと共通の構造スキーマ、設計チームへの要望書をまとめた。各カードで対象設計書・状態・シート分類ルールを確認できる。

/01-setup がシート役割の推定に読む（書く工程は無し）

roleTag 優先ルール

シートの固定セル A1 に役割タグの明記（roleTag）があれば、シート名マッチング（pattern）より優先する。役割タグが無い設計書はプロファイルのシート名 pattern で推定し、推定であることを J-01 の sheets[].matchSource（inferred）に記録する。

見方: 番号が判定の優先順位（小さいほど先に評価される）。

① roleTag（A1 セル明記） ② シート名 pattern（推定）

PROFILE-00 構造スキーマ

読む工程: /01-setup

7本のプロファイル JSON が共通で従う構造。unknownSheet / profileMismatch は停止させず調査・警告に倒す（機械FAILのみ停止・人間レビューは非ブロッキング）。

トップレベルキー内容

documentScopeenum: feature / shared_master / common / unknown

policiescanonicalSource・unknownSheet・profileMismatch（下表）
sheetRules[] の主キー内容
ruleId / matchType（exact/regex）/ patternシート名のマッチ条件（必須）
roleTag[]A1 セル役割タグの候補値。pattern より優先（任意項目）
roleenum: metadata / extract / asset / ignore_candidate / reference_only / unknown
outputContracts[]enum: J-01 / J-10 / J-11 / J-20 / J-30 / J-40 / J-60
priority（整数） / notes（string または null）マッチ優先度 ／ 補足
policies の主キー内容
canonicalSource正本の選び方（正とするシート/行）
unknownSheetenum: investigate（調査モードで候補提示・停止しない）/ warning（警告のみ）/ ignore（無視）
profileMismatchenum: investigate（調査モードへ・停止しない）/ warning（警告のみ）。いずれも停止しない

設計書フォーマット要望書

設計チームへ渡す依頼書。対応を待たずに現状の設計書のまま変換作業（プロファイル推定）を開始でき、対応が進むほど AI の推定が減り、変換結果の間違いと手直しが着実に減る。

1. 各シートに roleTag を明記固定セル A1 に候補一覧から役割タグを1つ記入。シート名からの推測を避け、誤分類による手直しを減らす。
2. ファイル名に ID 種別を明記機能ID / 画面ID / ジョブID のどれか分かる命名にする。出力の格納先（画面・処理・バッチ）の取り違えを防ぐ。
3. 表形式シートに行IDの列を追加各行に一意な行ID（連番可）。行の追加・削除で位置がずれても出典を安定して指し示せる。
4. テーブル関連（FK）を書く欄を設置ER図は設計書に明記された関連だけを根拠にする。AIが関連を推測して線を引くことはしない。
5. 結合セル・非表示の行列を避けるデータは1セル1値。結合セルや非表示部分は機械読み取りが不安定になり、取りこぼし・位置ずれの原因になる。
