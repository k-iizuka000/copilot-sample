/00 フォーマット調査 調査

原本: 00-d00-format-survey.prompt.md
このプロンプトは、未知・改訂済みのExcelフォーマットだけを対象にシートを棚卸しし、調査レポートと候補Profileを作る工程で、通常の変換フローには含まれない。図は入力→手順→出力を左から右に読み、手順をクリックすると使う入力・出す出力だけが光る。

サマリー

実行条件・回数（RUNBOOKより） 未知または改訂済みフォーマットだけ。調査対象1冊につき1回
標準モデルと条件（RUNBOOKより） GPT-5.4 Medium — 未知形式の分類と候補Profile作成に使用
前工程 → この工程 → 後工程 G0 入力確定（人間） → /00 フォーマット調査 → 人間が候補Profileを承認・登録 → /01 棚卸し・ルーティング
使用条件（原本より）: 新しい設計書種類、改訂されたテンプレート、既存プロファイルにないシートを初めて扱うときだけ使用する。通常の変換では実行しない。

手順（原本の順序のまま）

1 正確なシート名、表示・非表示状態、使用範囲を列挙する 対象設計書のシート構成を棚卸しする
2 各シートを extract / metadata / asset / reference_only / ignore_candidate / unknown へ分類する
3 各論理表の見出し、ヘッダ段数、繰り返し単位、主キー候補、ブロック境界を記録する
4 結合セル、数式、非表示行・列、コメント、drawing、media、画像、複数表の有無を記録する
5 既存プロファイルで処理可能か判定する
6 判断できない項目を、人間が回答可能な確認質問として記録する
7 調査結果から candidateProfileId を使った provisional 状態の候補Profileを作る 未確認のシートルールは推測で確定せず unknown / UNKNOWN とし、理由をnotesへ記録する

停止条件・やらないこと

  • 新しい設計書種類、改訂されたテンプレート、既存プロファイルにないシートを初めて扱うとき以外は使用しない（通常の変換では実行しない）。
  • 未確認のシートルールを推測で確定しない。unknown / UNKNOWN を使い、人間確認が必要な理由をnotesへ記録する。
  • 候補Profileを既存の profiles/ へ自動登録しない。
  • PROFILE-INDEX.md を変更しない。
人間ゲート: 人間が候補Profileの内容とSchema適合（PROFILE-00.schema.json）を確認し、承認して登録するまで /01-e2j-inventory-route へ進まない。
