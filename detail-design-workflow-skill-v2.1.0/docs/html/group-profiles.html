設計書プロファイル

このページの目的と見方: プロファイルは対象の設計書（Excel）のシート構成を判定するルール集で、シートごとに担当するE2Jスキルと書き込み先のJ-*契約を決める。設計書プロファイル7本（PROFILE-01〜06、02Bを含む）＋全プロファイルが従う構造定義（PROFILE-00）の計8件をカード化した。
参照元（このプロファイル群を参照ファイルとして読むPrompt）: /00 /01 /02 /03 /04 /05 /06 /07

プロファイル一覧（PROFILE-INDEX.md より）

見方: 1行=1プロファイル。「ID」は下の詳細カードへ、「主な後続Prompt」は各プロンプトページへリンクする。

ID対象主な後続Prompt
PROFILE-01画面帳票設計書 /02, /03, /07
PROFILE-02処理機能記述書 /04, /05
PROFILE-02Bバッチ設計書（暫定） /04, /05
PROFILE-03エンティティ・データモデル定義書 /05, /07
PROFILE-04VIEW定義書 /05
PROFILE-05権限マトリクス /06, /07
PROFILE-06共通規約・文書（D00調査用の暫定入口） /00, /06

プロファイル自体の構造は PROFILE-00（スキーマ） に従う。

暫定（provisional）プロファイルの扱い（PROFILE-INDEX.md より）: provisional のプロファイルは、記載前提と実物が一致する場合だけ使用する。PROFILE-06 はそのまま通常変換に使用せず、/00-d00-format-survey で具体的な候補Profileを作るための入口とする。実際のシート名・見出しと一致しない場合は、推測で既存プロファイルを流用せず、/00-d00-format-survey を実行して人間確認へ戻る。
設計書プロファイル7本（PROFILE-01〜06、02Bを含む）は policies のうち5項目が共通: hiddenRows=include_and_mark（非表示行も含めて明示マーク） ／ formula=display_and_formula（表示値と数式を両方保持） ／ assets=separate_manifest（画像等は別マニフェスト） ／ unknownSheet=fail ／ profileMismatch=fail（想定外シート・プロファイル不一致はともに停止）。差があるのは canonicalSource（正本の判定基準）のみで、各カードに記載する。

役割（role）・状態（status）の凡例

見方: 下の日本語は原本の enum 値の言い換え。以下の各プロファイルの表の「役割」列・見出しの status はこの値のいずれかを取る。

metadata＝メタ情報 extract＝抽出対象 asset＝素材（画像等） reference_only＝参照のみ（正本に混ぜない） ignore_candidate＝除外候補 unknown＝未確定
status: stable＝安定（確定済み） status: provisional＝暫定（実物との一致を要確認）

PROFILE-00 — プロファイルの構造定義（スキーマ）

原本: profiles/PROFILE-00.schema.json

PROFILE-01〜06 のような設計書プロファイルそのものではなく、それら全てが従う構造定義。profileId / version / documentType / status / documentScope / description / sheetRules / policies の8フィールドを必須とする。

status enumstable / provisional
documentScope enumfeature / shared_master / common / unknown
sheetRules[].role enummetadata / extract / asset / ignore_candidate / reference_only / unknown
sheetRules[].skills enumE2J-00〜E2J-06 / NONE / UNKNOWN
sheetRules[].outputContracts enumJ-01 J-10 J-11 J-20 J-30 J-40 J-60
policies 必須キーhiddenRows formula assets canonicalSource unknownSheet profileMismatch

スキーマの制約（allOf）: sheetRules の skills に E2J-0X が含まれるなら outputContracts に対応する J-* を含み、その逆も成り立つ（E2J-00↔J-01, E2J-01↔J-10, E2J-02↔J-11, E2J-03↔J-20, E2J-04↔J-30, E2J-05↔J-40, E2J-06↔J-60）。
