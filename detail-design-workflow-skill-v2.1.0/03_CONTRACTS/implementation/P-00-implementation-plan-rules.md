# P-00 実装計画共通契約

## 目的

詳細設計Markdownを、人間が選択できる1タスク単位の実装計画へ変換する。

## タスク分割原則

- 1行につき1つの明確な目的。
- 原則として対象ファイルまたは対象責務を特定する。
- 前提タスク、設計書参照、完了条件、テスト方法を必須にする。
- 人間が差分をレビューできない大きさにしない。
- 設計書から推測しなければ実行できないタスクを作らない。
- blocking issueに依存するタスクは`要確認`にする。

## 標準順序

1. データ構造
2. Entity、DTO、Form
3. Repository、Mapper
4. Service
5. Validator
6. Controller
7. 画面テンプレート、画面部品
8. JavaScript、画面制御
9. 単体テスト
10. ブラウザテスト
11. 総合確認

機能構造に応じて変更できるが、依存先を依存元より先に置く。

## ステータス

`未着手`, `実装中`, `確認待ち`, `修正中`, `テスト待ち`, `要確認`, `保留`, `完了`

AIが実装を終えた時点は`確認待ち`であり、`完了`ではない。
