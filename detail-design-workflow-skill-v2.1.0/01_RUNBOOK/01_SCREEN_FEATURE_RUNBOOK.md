# 画面・機能単位の標準作業手順

この文書が、日々の実行順序の正本です。通常は1画面または1機能につき、専用のrunフォルダを1つ作ります。

## 0. 作業フォルダを作る

`run-template/FEATURE-ID`をコピーし、`FEATURE-ID`を実際の機能IDへ変更する。`run-request.json`へ機能ID、機能名、設計書パス、版、担当者を記入する。

### G0 入力確定

人間が、対象設計書の正本、版、機能ID、機能名を確認する。確認できない場合は開始しない。

## 1. 設計書を棚卸しする

対象の設計書1冊ごとに実行する。

```text
/01-e2j-inventory-route
```

画面帳票設計書と処理機能記述書がある場合は2回実行し、それぞれJ-01を作る。1回に複数冊を渡さない。

## 2. 画面帳票設計書をJSON化する

E2J-00のroutingPlanを優先し、必要なものだけ実行する。

```text
/02-e2j-ui-structure
```

対象例: `項目`, `パラメータ`, レイアウト中の明示情報。

```text
/03-e2j-ui-behavior
```

対象例: `項目制御`, `バリデーション`, `イベント`, `メッセージ`。

```text
/07-e2j-assets
```

対象例: `レイアウト`内の画像、図形、drawing、media、読取不能コメント。

大きなシートは、項目番号、イベントID、表示モード等で論理ブロックに分ける。

## 3. 処理・データ・権限をJSON化する

```text
/04-e2j-process-batch
```

対象例: `処理機能記述`, `検索要領`, `更新要領`。

```text
/05-e2j-data-query-interface
```

対象例: `項目DB対応表`, 対象エンティティ, 対象VIEW, ファイル・外部連携。

```text
/06-e2j-common-permission
```

対象画面または機能に適用される権限・共通規約がある場合だけ実行する。

## 4. 各JSONを原本と照合する

J-01、J-10、J-11、J-20、J-30、J-40、J-60のうち、作成したファイル1件ごとに実行する。

```text
/08-ev-source-fidelity
```

`FAIL`は元のE2J工程へ戻す。`PASS_WITH_WARNINGS`は警告を人間が読み、受容または修正を判断する。

### G1 JSON承認

必要JSONのEV-01がすべて`PASS`、または人間が受容した`PASS_WITH_WARNINGS`であることを確認する。blocking issueが残る場合は進まない。

## 5. 詳細設計Markdownを作る

```text
/09-j2m-detail-design
```

続けて検証する。

```text
/10-ev-markdown-integrity
```

### G2 詳細設計承認

人間が、`90-open-issues.md`、`99-traceability.md`、各詳細設計を確認する。EV-02が`FAIL`またはblocking issueがある場合は実装計画へ進まない。

## 6. 実装計画を作る

```text
/11-m2p-implementation-plan
```

続けて検証する。

```text
/12-ev-implementation-plan
```

### G3 実装計画承認

人間が、タスク粒度、実装順、対象ファイル、完了条件、テスト方法、前提タスクを確認し、Front Matterの`humanApproval`を承認状態へ更新する。

## 7. 実装計画を1件ずつ実装する

実装計画から、ステータスが`未着手`で、前提タスクが完了している1件を選ぶ。

```text
/13-imp-execute-task
```

実装が終わったら、同じタスク番号でレビューする。

```text
/14-rev-task
```

### G4 タスク承認

人間が差分、R-10、R-20、テスト結果を確認する。

- 問題なし: 実装計画の状態を`完了`へ更新。
- 修正必要: `修正中`へ更新し、同じタスク番号で`/13`から再実行。
- 仕様確認必要: `要確認`へ更新し、回答まで依存タスクを開始しない。

全タスクでこの手順を繰り返す。

## 8. 画面・機能全体を最終レビューする

全タスクが整理されたら実行する。

```text
/15-rev-feature
```

### G5 機能完了承認

人間がR-30を確認し、全Record ID、実装タスク、実装箇所、テスト、レビューが追跡できることを確認する。AIの`PASS`だけで完了にしない。

## 中断・再開

各工程の出力ファイルが再開地点になる。前工程の出力と評価結果が存在しない場合、後工程から開始しない。
