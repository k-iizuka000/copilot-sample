# 13-imp-execute-task

## 実行パラメータ

- **featureId**: `${input:featureId:機能ID}`
- **taskId**: `${input:taskId:実装計画番号}`
- **planPath**: `${input:planPath:P-10実装計画}`
- **detailDesignDirectory**: `${input:detailDesignDirectory:詳細設計Markdown}`
- **resultPath**: `${input:resultPath:R-10実装結果出力先}`

## 実行指示（全文）

## 参照契約

- `P-10` 実装計画
- `R-10` タスク実装結果
- 指定タスクが参照する詳細設計Markdown
- プロジェクト共通Instructionsと実装規約

## 前提チェック

1. 指定タスクが1件だけである。
2. ステータスが`未着手`または人間が再実行を承認した`修正中`である。
3. 前提タスクがすべて`完了`である。
4. `要確認`または`保留`ではない。
5. 対象、完了条件、テスト方法が明確である。

前提を満たさない場合、実装せず`blocked`としてR-10を出す。

## 唯一の役割

指定された実装計画番号1件だけを実装し、必要なテストを作成または実施して、R-10を出力する。

## 手順

1. タスク行と参照された詳細設計だけを読む。
2. 変更予定ファイルと実装方針を短く整理する。
3. 対象範囲だけを変更する。
4. 完了条件を確認できるテストを作成または更新する。
5. VS Codeの利用可能なテスト機能で実行できる場合だけテストを実行する。
6. ターミナルまたはCLIは使用しない。実行できないテストは`未実施`として理由を記録する。
7. 差分、テスト、未確認事項をR-10形式で出力する。
8. 実装計画を自動で`完了`へ変更しない。推奨状態は原則`確認待ち`とする。

## 禁止

- 指定タスク以外の改善やリファクタリング。
- 設計書にない業務仕様の追加。
- 関係のないファイル変更。
- テスト未実施を成功として報告すること。
- 人間確認なしの完了扱い。

## 最終応答

- 指定された出力ファイルを作成または更新する。
- チャット本文には、結果、出力先、件数、判定、blocking issueだけを簡潔に報告する。
- 指定された出力先以外を変更しない。
