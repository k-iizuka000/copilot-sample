# E2J-03 処理機能・バッチ抽出

## 参照契約

- `I-00`, `J-00`, `J-20`, `J-99`
- `PROFILE-02`または`PROFILE-02B`

## 許可されたrecordType

- `process`
- `process_step`
- `search_specification`
- `update_specification`
- `business_rule`
- `error_rule`
- `transaction_rule`
- `batch_control`

## 手順

1. 指定された1シートまたは1論理ブロックだけを読む。
2. イベントIDまたは処理節をブロック境界として保持する。
3. 処理機能記述は入力、処理内容、メッセージ、出力を分離する。
4. 検索要領は検索要領番号ごとに、入力テーブル、絞込、結合、ソート、出力項目を抽出する。
5. 更新要領は対象テーブル、更新種別、編集条件、更新項目を抽出する。
6. バッチの場合は起動条件、終了条件、再実行、リトライ、リカバリ、コミット境界が明記された範囲だけ抽出する。
7. 処理順序を原文どおりに保持し、文章を要約しすぎない。
8. `J-20` JSONだけを指定出力先へ書き込む。

## やらないこと

- Javaクラスやメソッドへの割り当て。
- 一般的な例外処理、トランザクション、リトライの補完。
- 記載のないSQL、DB更新、出力項目の追加。

## 共通禁止事項

- 設計書にない仕様を補完しない。
- 設計書以外の資料、既存コード、Web、別ブックを参照しない。
- 元ファイルを変更しない。
- 指定出力先以外を変更しない。
- 正本、旧版、参照用、派生物を混ぜない。
- 読取不能を空欄や推測値で埋めない。
- ターミナルまたはCLIを使用しない。

## 共通停止条件

次のいずれかを検出した場合、`status=failed`または`status=partial`とし、blocking issueを出す。

- 対象ブックが複数ある。
- 指定プロファイルと実際のシート構成が一致しない。
- 正本候補が競合する。
- 入力が途中で切れている。
- 見出し、繰り返し単位、ブロック境界を特定できない。
- 出典を付けられない。

## 共通セルフチェック

1. 出力は指定Schemaに従い、定義外キーを追加しない。
2. 不明値は`null`とする。
3. 確定レコードには1件以上の`sourceRefs`がある。
4. 全sourceUnitがcoverageに存在する。
5. `sourceUnitCount = accountedSourceUnitCount`かつ`unaccountedSourceUnitCount = 0`である。
6. 条件5を満たせない場合、`complete`にしない。
7. 数式を読める場合、表示値と数式文字列を両方保持する。
8. 非表示行・列を、非表示という理由だけで除外しない。
9. 画像、図形、コメント等をアセットまたはissueとして残す。
