# 実行順序

## 画面・機能単位

1. G0: 対象設計書、版、機能ID、出力先を人間が確定する。
2. 設計書1冊ごとに`/01-e2j-inventory-route`を実行する。
3. routingPlanに従い、`/02`〜`/07`の必要なプロンプトを、1シートまたは1論理ブロック単位で実行する。
4. 作成したJ-* JSONごとに`/08-ev-source-fidelity`を実行する。
5. G1: `FAIL`がなく、警告を人間が受容したことを確認する。
6. `/09-j2m-detail-design`を実行する。
7. `/10-ev-markdown-integrity`を実行する。
8. G2: 詳細設計と未確定事項を人間が承認する。
9. `/11-m2p-implementation-plan`を実行する。
10. `/12-ev-implementation-plan`を実行する。
11. G3: 実装計画を人間が承認する。
12. 実装計画から1件を選び`/13-imp-execute-task`を実行する。
13. `/14-rev-task`を実行し、G4で人間が完了または修正を判断する。
14. 全タスクで12〜13を反復する。
15. `/15-rev-feature`を実行し、G5で人間が機能完了を判断する。

## 再実行

生成物を手で直して評価を通さない。原本、入力スナップショット、プロファイル、または生成プロンプトの原因を直し、同じ工程から再実行する。
