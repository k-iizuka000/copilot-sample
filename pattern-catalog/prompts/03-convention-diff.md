# 調査プロンプト03: 規約と実態の差分抽出

- 用途: 明文規約とDCSソースの実態を突き合わせ、明文化されていないローカルルール（暗黙知）を抽出する
- モデル: GPT-5.4（effort high）。ルールの一貫性判断を含むためmini系では実行しない
- モード: Agent（DCSソースをワークスペースから読むため）
- 事前準備:
  1. 既存の明文規約文書（コーディング規約など）をワークスペースに置く。Excelならマークダウン変換する
  2. 垂直掘り済みのDCS機能を2〜3個選び、パスを控える（垂直掘りと同じ機能を使うと突き合わせ結果を再利用できる）

---

## プロンプト本文（コピーして使う）

明文規約とDCSソースの実態を突き合わせて、明文化されていないルールを抽出してください。

### 入力

- 明文規約: {規約文書のパス}
- DCSソース: {機能2〜3個ぶんのファイル群のパス}

### やること

1. 明文規約の各ルールが、DCSソースで実際に守られているかを確認する
2. 明文規約に書かれていないが、DCSソースで一貫して守られているルールを抽出する。観点: 命名 / レイヤ責務 / 例外処理 / トランザクション / ログ / DBアクセス / テスト
3. 抽出したルールを conventions.md の表形式で出力する

### 守ること

- ルールには必ず根拠（DCSの該当ファイル・箇所）を付ける
- 1機能でしか確認できていないルールは確信度を「中」以下にする
- 規約と実態が食い違う箇所は、どちらが正しいか判断せず「食い違い」として事実だけ報告する
- 規約に書いてあり実態も一致しているルールは出力しない（このドキュメントは暗黙知の言語化が目的のため）

### 出力

1. 横断ルール追記行（conventions.md の表形式）
2. 明文規約と実態の食い違いリスト（有識者確認の材料）
