# 調査プロンプト02: 垂直掘り（設計書 ⇔ DCS 突き合わせ）

- 用途: 代表機能1つの設計書全シートとDCSの同等機能を突き合わせ、共通対応マップの行とパターンレシピの草案を作る
- モデル: GPT-5.4（effort high）。mini系では実行しない
- モード: Agent（DCSソースをワークスペースから読むため）
- 並列: 実行中は他の重い作業を並列しない
- 事前準備:
  1. 対象機能の設計書をマークダウン変換してワークスペースに置く
  2. DCSの同等機能（同種の画面タイプの機能）を特定し、ファイル群のパスを控える
  3. 現時点の `traceability-map.md` と対象パターンのレシピ（あれば）をワークスペースに置く

---

## プロンプト本文（コピーして使う）

DWSの設計書とDCSの実装を突き合わせて、対応関係を抽出してください。

### 入力

- 設計書: {設計書mdのパス}（画面設計書7シート + 機能設計書5シート）
- DCS実装: {DCS同等機能のファイル群のパス}
- 既存の対応マップ: traceability-map.md

### やること

1. 設計書の各シートについて、記載項目を列挙する
2. 各記載項目が、DCS実装のどのファイル・どの箇所（クラス / メソッド / フィールド / テンプレート要素）に対応するかを特定する
3. 対応関係を traceability-map.md と同じ表形式で出力する
4. DCS実装のうち、設計書のどの項目にも対応しない部分を「定型部分」（フレームワーク都合・全機能共通と思われるコード）として、ファイル別に列挙する
5. 設計書の項目のうち、実装のどこにも反映されないものを「未使用候補」として列挙する

### 守ること

- 対応が見つからない項目は「不明」と書く。推測で埋めない
- 推測を含む対応は確信度を「低」とし、推測の根拠を書く
- 既存の対応マップと矛盾する対応を見つけたら、上書きせず「矛盾」として報告する
- 業務ロジックの正解は設計書である。DCSは作り方の参考であり、DCSの挙動を仕様の正解として扱わない

### 出力

1. 対応マップ追記行（traceability-map.md の表形式）
2. 定型部分リスト（ファイル別。「全機能ほぼ同じ」と「機能ごとに変わる」の切り分け付き）
3. 未使用候補リスト（設計書フォーマット変更の削除候補材料）
4. 矛盾・不明点リスト（質問票の材料）

## 検証モード（同パターン2機能目以降で使う差し替え文）

上記プロンプト本文の「やること」を以下に差し替える。

### やること（検証モード）

1. 既存の対応マップと対象パターンのレシピを読む
2. この機能の設計書とDCS実装が、マップ・レシピの記述どおりに対応しているかを確認する
3. 一致した行は確認済みとして報告する（確信度を「高」に上げる根拠になる）
4. 一致しなかった箇所だけを「差分」として詳細に報告する

守ること・出力の形式は同じ。差分ゼロならゼロと報告する。
