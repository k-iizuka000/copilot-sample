# 調査プロンプト01: 機能一覧のパターン分類

- 用途: 417機能を画面タイプで分類し、レシピが何枚必要か・どの機能から掘るかを決める
- モデル: mini系で可（分類の最終判断は人間が行うため）
- モード: Chat
- 事前準備: 機能一覧をマークダウン変換してワークスペースに置く

---

## プロンプト本文（コピーして使う）

DWSの機能一覧を画面タイプで分類してください。

### 入力

- 機能一覧: {機能一覧mdのパス}

### やること

1. 各機能を画面タイプで分類する。分類名は一覧の実態から導く（例: 検索一覧、詳細照会、登録・更新、帳票出力、バッチ。これはあくまで例であり、実態に合う分類を作ること）
2. 分類ごとに、判定基準（機能一覧のどの情報を見てそのタイプと判定したか）を明記する
3. 分類ごとに件数を集計する
4. 分類ごとに、垂直調査の代表候補となる機能を3つ挙げる（標準的・典型的なものを優先する）

### 守ること

- 判定に迷った機能は無理に割り振らず「未分類」に入れる
- 分類は5〜12個程度に収める。細かすぎる分類は統合する
- 機能一覧に無い情報を推測で補わない

### 出力

1. パターン一覧表（パターン名 / 判定基準 / 件数 / 代表候補3機能）
2. 未分類の機能リスト（迷った理由付き）
