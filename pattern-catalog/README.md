# パターンカタログ調査キット

設計書・DCSソース・既存規約から、実装に必要なローカルルールを抽出し、
「共通対応マップ + パターン別レシピ + 横断ルール集」の3点セットに言語化するためのキット。

個人PC（claude-work）で設計し、copilot-sample 経由で仕事PCに転写して使う。

## 完成形（3点セット）

| 成果物 | 内容 | テンプレート |
|---|---|---|
| 共通対応マップ | 設計書の各シート・記載項目が、実装ファイルのどこに反映されるかの対応表。フォーマットが全機能統一のため、全機能共通で1枚だけ維持する | `templates/traceability-map.md` |
| パターン別レシピ | 画面タイプごとの実装手引き。DCS代表実装への参照、定型部分と機能固有部分の切り分けを含む | `templates/pattern-recipe.md` |
| 横断ルール集 | 明文規約に書かれていないが、DCSで一貫して守られている実態ルール（＝暗黙知）の言語化 | `templates/conventions.md` |

**Done基準**: 調査に使っていない未知の1機能を、この3点セットだけを読んだCopilotが
人間の追加説明なしで実装できること。引き渡し用デモ実装がそのまま検証を兼ねる。

## 入力と器の対応

| 入力 | 見方 | 流し込む先 |
|---|---|---|
| 既存設計書（Excel→md） | 全量は読まない。代表1機能ぶんの各シート・各項目を「最終的にコードのどこへ行くか」でラベリング | 対応マップ |
| 既存ソース（DCS） | 機能単位で約10ファイルを読む。役割分担・設計書項目との対応・「全機能共通の定型」と「機能固有」の切り分け | 対応マップ + レシピ |
| 既存規約（明文文書） | 明文ルールとDCSの実態の差分を取る。実態にあって明文に無いもの＝抽出すべきローカルルール | 横断ルール集 |

## 進め方（調査ループ）

| # | 作業 | 実行 | 使うもの | モデル・負荷 |
|---|---|---|---|---|
| 1 | 機能一覧をパターン分類 | 仕事PC・Copilot | `prompts/01-pattern-classification.md` | mini系可・単独 |
| 2 | 分類を確認し、パターンごとの代表機能を決める | 人間 | 分類結果 | - |
| 3 | 代表機能の垂直掘り（設計書⇔DCS突き合わせ） | 仕事PC・Copilot | `prompts/02-vertical-dig.md` | GPT-5.4 high・単独 |
| 4 | マップ・レシピ草案をレビュー | 人間 | 草案 | - |
| 5 | DCS由来の理解を有識者確認 | 人間 | 確信度・有識者確認欄 | - |
| 6 | 同パターンの別機能1つで検証、差分を例外として追記 | 仕事PC・Copilot | `prompts/02`（検証モード） | GPT-5.4 high |
| 7 | 規約と実態の差分抽出 | 仕事PC・Copilot | `prompts/03-convention-diff.md` | GPT-5.4 high |

- 3〜7 をパターンごとに繰り返す。マップは回すたびに埋まり、後のパターンほど差分だけで済む
- 並列は最大2まで。垂直掘り同士は並列しない（重い作業は常に1本、並列するなら軽い分類・確認系と組み合わせる）
- 全プロンプト共通の掟: **推測で埋めない・不明は不明と書く・確信度を付ける・DCSを仕様の正解として扱わない**

## 副産物

垂直掘りで「実装のどこにも反映されない設計書項目」が見つかる。
これは設計書フォーマット変更（無駄トークン削減）の削除候補リストとしてそのまま使う。
