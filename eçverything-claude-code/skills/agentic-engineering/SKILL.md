# エージェント型エンジニアリング

AIエージェントが実装作業の大部分を担い、人間が品質とリスク管理を担保するエンジニアリングワークフローで、このスキルを使用します。

## 運用原則

1. 実行前に完了基準を定義する。
2. 作業をエージェントサイズの単位へ分解する。
3. タスクの複雑さに応じてモデル階層をルーティングする。
4. evalsと回帰チェックで測定する。

## 評価ファーストループ

1. capability evalとregression evalを定義する。
2. baselineを実行し、失敗シグネチャを取得する。
3. 実装を実行する。
4. evalsを再実行し、差分を比較する。

## タスク分解

15分単位ルールを適用します:
- 各単位は独立して検証可能であるべき
- 各単位には支配的なリスクが1つだけあるべき
- 各単位は明確な完了条件を示すべき

## モデルルーティング

- Haiku: 分類、定型変換、狭い編集
- Sonnet: 実装とリファクタリング
- Opus: アーキテクチャ、根本原因分析、複数ファイルの不変条件

## セッション戦略

- 密結合した単位ではセッションを継続する。
- 大きなフェーズ遷移後は新しいセッションを開始する。
- アクティブなデバッグ中ではなく、マイルストーン完了後にcompactする。

## AI生成コードのレビュー焦点

優先するもの:
- 不変条件とエッジケース
- エラー境界
- セキュリティと認証の前提
- 隠れた結合とロールアウトリスク

自動format/lintがすでにスタイルを強制している場合、スタイルだけの意見相違にレビューサイクルを浪費しないでください。

## コスト規律

タスクごとに追跡するもの:
- モデル
- トークン見積もり
- リトライ
- 経過時間
- 成功/失敗

下位階層が明確な推論ギャップで失敗した場合にのみ、モデル階層をエスカレーションします。
