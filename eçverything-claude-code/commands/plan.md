# Plan コマンド

このコマンドは **planner** エージェントを呼び出し、コードを書く前に包括的な実装計画を作成します。

## このコマンドの機能

1. **要件の再整理** - 何を作る必要があるかを明確にする
2. **リスクの特定** - 潜在的な問題やブロッカーを表面化する
3. **段階的な計画作成** - 実装をフェーズに分解する
4. **確認待ち** - 進行前に必ずユーザーの承認を得る

## 使用するタイミング

以下の場合に `/plan` を使用します:
- 新機能を開始するとき
- 重要なアーキテクチャ変更を行うとき
- 複雑なリファクタリングに取り組むとき
- 複数のファイル/コンポーネントに影響があるとき
- 要件が不明確または曖昧なとき

## 動作方法

planner エージェントは以下を行います:

1. **リクエストを分析**し、要件を明確な言葉で言い換える
2. **フェーズに分解**し、具体的で実行可能なステップにする
3. コンポーネント間の**依存関係を特定**する
4. **リスク**と潜在的なブロッカーを評価する
5. **複雑度**を見積もる（高/中/低）
6. **計画を提示**し、明示的な確認を待つ

## 使用例

```
ユーザー: /plan 市場が決済されたときにリアルタイム通知を追加したい

エージェント (planner):
# 実装計画: 市場決済のリアルタイム通知

## 要件の再整理
- ユーザーがウォッチしている市場が決済されたときに通知を送信する
- 複数の通知チャネル（アプリ内、メール、webhook）をサポートする
- 通知が確実に配信されるようにする
- 市場の結果とユーザーのポジション結果を含める

## 実装フェーズ

### フェーズ 1: データベーススキーマ
- id、user_id、market_id、type、status、created_at カラムを持つ notifications テーブルを追加する
- チャネル設定用の user_notification_preferences テーブルを追加する
- パフォーマンスのため user_id と market_id にインデックスを作成する

### フェーズ 2: 通知サービス
- lib/notifications.ts に通知サービスを作成する
- BullMQ/Redis を使用して通知キューを実装する
- 配信失敗時のリトライロジックを追加する
- 通知テンプレートを作成する

### フェーズ 3: 統合ポイント
- 市場決済ロジックに接続する（status が "resolved" に変わったとき）
- 市場にポジションを持つすべてのユーザーを取得する
- 各ユーザーの通知をキューに入れる

### フェーズ 4: フロントエンドコンポーネント
- ヘッダーに NotificationBell コンポーネントを作成する
- NotificationList モーダルを追加する
- Supabase subscriptions 経由でリアルタイム更新を実装する
- 通知設定ページを追加する

## 依存関係
- Redis（キュー用）
- メールサービス（SendGrid/Resend）
- Supabase real-time subscriptions

## リスク
- 高: メール到達性（SPF/DKIM が必要）
- 中: 1市場あたり1000人以上のユーザーがいる場合のパフォーマンス
- 中: 市場が頻繁に決済される場合の通知スパム
- 低: リアルタイム subscription のオーバーヘッド

## 見積もり複雑度: 中
- バックエンド: 4〜6時間
- フロントエンド: 3〜4時間
- テスト: 2〜3時間
- 合計: 9〜13時間

**確認待ち**: この計画で進めますか？（yes/no/modify）
```

## 重要事項

**重要**: planner エージェントは、あなたが "yes"、"proceed"、または同様の肯定的な返答で明示的に計画を確認するまで、**コードを書きません**。

変更したい場合は、次のように返答します:
- "modify: [変更内容]"
- "different approach: [代替案]"
- "skip phase 2 and do phase 3 first"

## 他のコマンドとの統合

計画後:
- `/tdd` を使用してテスト駆動開発で実装
- ビルドエラーが発生した場合は `/build-fix` を使用
- 完了した実装のレビューには `/code-review` を使用

## 関連エージェント

このコマンドは ECC が提供する `planner` エージェントを呼び出します。

手動インストールの場合、ソースファイルは次の場所にあります:
`agents/planner.md`
